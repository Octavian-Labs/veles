## Следующий PR — `фича/режим-безопасности`

Цель PR: ввести независимую ось режима безопасности, не реализуя сами проверки
границ раньше следующего этапа.

### Требования

- [ ] CLI принимает `--режим надёжно` и `--режим быстро`.
- [ ] Без флага выбирается `надёжно`.
- [ ] Неизвестное значение режима даёт русскую ошибку и ненулевой код.
- [ ] Режим хранится в состоянии генератора и доступен последующим этапам.
- [ ] `-O0/-O1` не меняет режим безопасности.
- [ ] Строгий `лог` одинаков в обоих режимах.
- [ ] В выводе/метаданных сборки достаточно данных, чтобы позднее различать
  кэш и диагностику разных режимов; формат кэша в этом PR не вводить.
- [ ] CI отдельно компилирует положительные и отрицательные случаи обоих режимов
  на Windows, Linux и macOS.
- [ ] Обновлены `README.md`, `docs/04-разум.md`, `docs/05-канон.md`,
  `ROADMAP.md`, этот файл и `SETUP_LOG.md`.

### Не входит

- проверки индексов;
- среда исполнения аварий границ;
- изменение представления строк и срезов;
- диагностический аллокатор;
- типы `размер`/`смещение`;
- интерфейсные файлы модулей.

## Очередь базовой безопасности

Каждый пункт — отдельная ветка и PR. Порядок менять только осознанным решением
с обновлением канона и ROADMAP.

### 1. `фича/режим-безопасности`

Состояние: **следующий**. Требования перечислены выше.

### 2. `фича/границы-массивов`

- [ ] Статическая ошибка для известного индекса вне `Т[N]` в обоих режимах.
- [ ] Динамическая проверка в `надёжно` до умножения на размер элемента.
- [ ] Знаковый индекс проверяется на `< 0`; беззнаковый — только на верхнюю
  границу.
- [ ] База и индекс вычисляются ровно один раз.
- [ ] Чтение и запись имеют отдельную диагностику.
- [ ] В `быстро` динамическая проверка не генерируется, статическая остаётся.

### 3. `фича/границы-срезов`

- [ ] Индексация `[]Т` проверяет `0 <= индекс < длина`.
- [ ] Создание `[начало..конец]` сначала проверяет порядок и верхнюю границу,
  затем вычисляет длину.
- [ ] Для `..=` проверяется переполнение `конец + 1`.
- [ ] Пустые срезы `[0..0]` и `[длина..длина]` допустимы.
- [ ] Срез сырого указателя в `надёжно` предупреждает о непроверяемой области.

### 4. `фича/границы-строк`

- [ ] `стр[индекс]` проверяется по байтам UTF-8.
- [ ] Индекс `длина` запрещён, пустая строка покрыта тестом.
- [ ] Срез строки использует те же проверки, что срез массива/среза.
- [ ] `стр_срез` не остаётся небезопасным обходом синтаксиса.

### 5. `фича/сбой-границы`

- [ ] Автоматически доступны `стд_сбой_границы` и `стд_сбой_среза`.
- [ ] Стабильные коды: 101 — граница, 102 — срез, 103 — память.
- [ ] Минимальная диагностика работает без подключения `консоль`.
- [ ] Реализации Windows, Linux, macOS не выделяют память в аварийном пути.
- [ ] Архитектура предусматривает файл, строку, индекс, длину и вид операции.
- [ ] СЛЕД останавливается на обработчике; сценарий добавлен в
  `след/ЗАДАЧИ.md` и Windows CI.

### 6. `фича/оптимизация-проверок`

- [ ] Корректный константный индекс не получает динамическую проверку.
- [ ] Канонический цикл может удалить проверку только при полном доказательстве.
- [ ] Сомнительная проверка сохраняется.
- [ ] `-O0/-O1` имеют одинаковую наблюдаемую безопасную семантику.

### 7. `фича/диагностика-памяти`

- [ ] Зафиксировать владение `стр` и будущей владеющей `Строка` отдельным
  проектным решением.
- [ ] `--память проверка`: таблица выделений, размеры, защитные значения,
  заполнение освобождённого блока, карантин, двойное/неизвестное освобождение,
  утечки при завершении.
- [ ] Не импровизировать borrow checker внутри генератора.

### 8. `фича/типы-размер-смещение`

- [ ] Добавить `размер` и `смещение`, ABI-совместимые на x86-64 с
  `нат.верх`/`цел.верх`.
- [ ] Устранить противоречие фиксированного и машинного смысла `верх`.
- [ ] Мигрировать стандартную библиотеку, затем компилятор и ИСКРУ.
- [ ] Не выполнять массовую смену одним коммитом.

### 9. `фича/интерфейсы-модулей`

- [ ] Явные `открыто`/`скрыто`, по умолчанию `скрыто`.
- [ ] Запрет доступа к скрытым именам из другого модуля.
- [ ] Интерфейс `.рми`: версии, цель, режим безопасности, ABI, экспорты,
  раскладки, зависимости и хеши.
- [ ] Повреждённый/чужой кэш молча перестраивается.
- [ ] Семантика `взять сист.файл` и квалифицированных имён сохраняется.

## Обязательная проверка каждого этапа

- [ ] Новый отрицательный тест сначала действительно падает.
- [ ] Нативный прогон проходит на Windows.
- [ ] РАЗУМ компилирует сам себя; два поколения дают идентичную ИСКРУ.
- [ ] ИСКРА собирается новым РАЗУМОМ.
- [ ] СЛЕД компилируется.
- [ ] Сиды PE64/ELF64/Mach-O обновлены, если изменился код компилятора.
- [ ] CI Windows/Linux/macOS зелёный.
- [ ] Документация не выдаёт будущую возможность за реализованную.

## Параллельные направления

Они не должны незаметно вытеснять текущий цикл базовой безопасности:

- версии канона и инструмент `переведи`;
- `вещ.*` и SSE;
- ОС на ВЕЛЕСЕ;
- атомы и параллелизм;
- AArch64/RISC-V;
- приборы и квантовые схемы;
- ЯР;
- развитие СЛЕДа по [след/ЗАДАЧИ.md](след/ЗАДАЧИ.md).
