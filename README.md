# ВЕЛЕС

**ВЕЛЕС** — самостоятельная русскоязычная экосистема нативного
программирования: от машинных инструкций до системного и будущего
высокоуровневого языка.

```text
ИСКРА  →  РАЗУМ  →  ЯР
  x86-64     системы     высокий уровень
     └────── СЛЕД ──────┘
```

ВЕЛЕС не использует виртуальную машину: ИСКРА формирует настоящие машинные
байты и исполняемые файлы PE64, ELF64 и Mach-O x86-64.

## Новая сессия: начать отсюда

Чтобы не восстанавливать состояние проекта по истории коммитов:

1. прочитать [AGENTS.md](AGENTS.md) — краткая обязательная памятка;
2. открыть [ЗАДАЧИ.md](ЗАДАЧИ.md) — точная следующая работа и критерии;
3. свериться с [ROADMAP.md](ROADMAP.md) — долгосрочные направления;
4. при изменении языка проверить [канон](docs/05-канон.md) и
   [спецификацию РАЗУМА](docs/04-разум.md);
5. для СЛЕДа использовать отдельный [задачник](след/ЗАДАЧИ.md).

**Текущая точка:** ось безопасности `--режим надёжно|быстро`, границы
массивов `Т[N]`, срезов `[]Т` и строк `стр` завершены: статические ошибки
в обоих режимах, динамические проверки в `надёжно`. Аварийные обработчики
`стд_сбой_границы`/`стд_сбой_среза`/`стд_сбой_памяти` завершают процесс
стабильными кодами 101/102/103 и печатают диагностику в stderr без
`консоль`. Доказанные индексы (`инд & (N-1)`, `инд % K`, переменные цикла
`для` в пределах коллекции) обходятся без динамической проверки; недоказанные
сохраняют код 101. Ось `--память проверка` ведёт учёт выделений: двойное и
неизвестное освобождение, порча огранки и магии заголовка, утечки при
завершении — код 104. Типы `размер`/`смещение` — машинные слова цели (на x86-64 синонимы
`нат.верх`/`цел.верх`); стандартная библиотека и ядро (`raz`, `иск`,
`след`) мигрированы семантически. Видимость модулей `открыто`/`скрыто`:
без префикса объявление скрыто и доступно только своему модулю; доступ
к скрытому имени из чужого модуля — ошибка компиляции. Интерфейсный кэш
`.рми` (`--кэш`, по умолчанию включён) ускоряет повторную сборку:
модуль читается из кэша без переразбора исходников, а выход побайтно
совпадает со сборкой из исходников.

## Состав экосистемы

### ИСКРА

Русский ассемблер x86-64, написанный на РАЗУМЕ.

- русские мнемоники и регистры;
- метки, константы, выражения, секции, данные и выравнивание;
- кодирование настоящих инструкций x86-64;
- Windows DLL-импорты и системные вызовы Linux/macOS;
- эмиттеры PE64, ELF64 и Mach-O;
- нативные сиды для Windows, Linux и macOS x86-64.

### РАЗУМ

Статически типизированный системный язык, компилируемый в текст ИСКРЫ.
Компилятор написан на самом РАЗУМЕ.

- явные типы, указатели, массивы, срезы, записи и перечисления;
- функции, методы, косвенные вызовы и внешние функции;
- ручная память без обязательного сборщика мусора;
- модули `взять`, точечные пути и платформенные варианты;
- видимость объявлений `открыто`/`скрыто`, по умолчанию скрыто;
- интерфейсный кэш `.рми`: модули из кэша без переразбора, ключ —
  цель, режим, память, оптимизация и хеши исходника с зависимостями;
- диагностика типов печатает написанные имена: `размер`/`смещение`
  не сводятся к внутренним `нат.верх`/`цел.верх` в сообщениях;
- прагма `;версия N` в первой строке и конвейер устаревания:
  `:=`, `бул`, плоские `целN`/`безN` предупреждают в stderr;
  `;версия` действует и в `.иск` — РАЗУМ эмитирует её в вывод;
- `переведи` — мигратор устаревших исходников на актуальный канон
  (`переведи файл.раз`): `бул`→`лог`, `целN`/`безN`→`цел.*`/`нат.*`,
  `:=`→`введи`; строки, комментарии и `искра:`-блоки сохраняются
  побайтно, повторный запуск ничего не меняет;
- вставки `искра:` для системного кода;
- `-O0/-O1`, константная свёртка, регистровые локали и пипхол;
- независимая ось безопасности `--режим надёжно|быстро`, по умолчанию
  `надёжно`; режим фиксируется прагмой `;режим` в сгенерированной ИСКРЕ;
- строгий `лог`: только `нет`/`да`, без истинности «ноль/не ноль».

Канонические объявления:

```raz
счёт цел.верх = 0
введи готово = счёт == 0

если готово:
    счёт += 1
```

`:=` пока распознаётся как устаревшая переходная форма, но в новом коде не
используется.

### ЯР

Будущий язык высокого уровня. Сейчас существует черновая спецификация;
реализация ещё не начата. Текущая работа сосредоточена на безопасности и
устойчивости РАЗУМА и цепочки ИСКРА → машинный код.

### СЛЕД

Машинный отладчик PE64/Windows x64, написанный на РАЗУМЕ поверх Win32 Debug
API. Поддерживает процессы и потоки, программные точки, одиночный шаг,
регистры, память, DR0-наблюдение и эвристическую карту символов из ИСКРЫ.

Состояние и подтверждённые дефекты: [след/ЗАДАЧИ.md](след/ЗАДАЧИ.md).

## Фактическое состояние

| Возможность | Windows x64 | Linux x64 | macOS x86-64 |
|---|---:|---:|---:|
| ИСКРА x86-64 | работает | работает | работает |
| РАЗУМ | работает | работает | работает |
| Формат | PE64 | ELF64 | Mach-O |
| Платформенная библиотека | работает | работает | работает |
| Самосборка и фикс-точка | CI | CI | CI |
| СЛЕД | работает | не реализован | не реализован |

AArch64 и RISC-V — будущие отдельные кодеры. Переносимость означает сборку
одного исходного текста под выбранную пару «система-машина», а не запуск одного
бинарника на разных ОС.

## Самодостаточная цепочка

Python использовался только как ранние строительные леса. Текущая цепочка
сборки не зависит от Python:

```text
исходник .раз
    ↓  raz/разум*
текст ИСКРЫ .иск
    ↓  искра*
PE64 / ELF64 / Mach-O x86-64
```

В репозитории находятся шесть нативных сидов:

```text
искра.exe       raz/разум.exe       Windows PE64
искра           raz/разум           Linux ELF64
искра_мак       raz/разум_мак       macOS Mach-O x86-64
```

Компилятор собирает собственный исходник, новый бинарник повторяет сборку, а
ИСКРА двух поколений сравнивается побайтно. CI выполняет это на трёх ОС.

### ИЩИ

Нативная утилита поиска UTF-8-текста, написанная на РАЗУМЕ. Показывает строки
и столбцы, умеет искать без учёта регистра, фильтровать расширения и
рекурсивно обходить каталоги Windows. Сборка и примеры находятся в
[`ищи/README.md`](ищи/README.md).

Идеи следующих небольших программ и игр собраны в
[`Идейник.MD`](Идейник.MD).

## Быстрый старт

```text
git clone https://github.com/Octavian-Labs/veles.git
cd veles
```

### Windows

```powershell
cmd /c "raz\разум.exe < examples\вычисления.раз > вычисления.иск"
cmd /c "искра.exe < вычисления.иск > вычисления.exe"
.\вычисления.exe
```

Ожидаемый код выхода — `55`.

### Linux x86-64

```text
chmod +x raz/разум искра
./raz/разум --цель linux < examples/выход_linux.раз > выход.иск
./искра < выход.иск > выход
chmod +x выход
./выход
```

Ожидаемый код выхода — `42`.

### macOS x86-64

```text
chmod +x raz/разум_мак искра_мак
codesign -s - --force raz/разум_мак искра_мак
./raz/разум_мак --цель macos < examples/выход_linux.раз > выход.иск
./искра_мак < выход.иск > выход
chmod +x выход
codesign -s - --force выход
./выход
```

На Apple Silicon требуются Rosetta 2 и запуск x86-64-бинарников. CI использует
нативный Intel runner.

## Безопасность РАЗУМА

Уже реализовано:

- условия `если`/`а если`/`пока` принимают только `лог`;
- `не`/`и`/`или` принимают только `лог`;
- числа и указатели не преобразуются в `лог`;
- значения `лог` нормализуются до `0`/`1`;
- присваивание не является выражением;
- режимы безопасности `надёжно` (по умолчанию) и `быстро` — независимая
  от `-O0/-O1` ось, неизвестное значение флага `--режим` отклоняется
  ошибкой компилятора;
- границы массивов `Т[N]`: константный индекс вне границ — ошибка
  компиляции в обоих режимах; в `надёжно` динамическая проверка завершает
  процесс кодом 101 (в `быстро` не генерируется);
- границы срезов `[]Т`: индексация по длине — код 101, создание `a..b`/`a..=b`
  проверяет порядок и верхнюю границу — код 102; пустые срезы допустимы;
  срез сырого указателя предупреждает о непроверяемой области;
- границы строк `стр`: индексация по байтам UTF-8 — код 101, индекс `длина`
  и пустая строка запрещены; `стр_срез` проверяет диапазон всегда — код 102,
  обхода синтаксиса нет;
- аварийные обработчики `стд_сбой_границы`/`стд_сбой_среза`/`стд_сбой_памяти`:
  стабильные коды 101/102/103, диагностика в stderr без `консоль`, сбой
  выделения памяти — код 103;
- доказуемое удаление динамических проверок: `инд & (N-1)`, `инд % K`,
  переменная `для и в мин..предел` и `для и в кол` не получают проверку;
  мутация переменной или коллекции в теле снимает доказательство;
- диагностическая память `--память проверка`: связный список блоков,
  магия заголовка, огранка `0x5A`, отравление `0xDD`, карантин;
  чужой/повторный указатель, порча огранки или магии и утечки при
  завершении — код 104 с диагностикой в stderr.

Следующая последовательность, каждый пункт отдельным PR:

1. ~~стабильные обработчики и коды 101/102/103~~ — выполнено;
2. ~~оптимизация доказанно лишних проверок~~ — выполнено;
3. ~~диагностическая память~~ — выполнено;
4. ~~типы `размер`/`смещение`~~ — выполнено (библиотека и ядро
   мигрированы);
5. ~~интерфейсы и кэш модулей~~ — выполнено (видимость и `.рми`).

Сырой указатель принципиально не несёт длину.

## Проверка изменений

Нативный прогон Windows из корня:

```powershell
cmd /c "raz\разум.exe < тесты\прогон.раз > прогон.иск"
cmd /c "искра.exe < прогон.иск > прогон.exe"
.\прогон.exe
```

Текущий ожидаемый результат:

```text
24/24 ок, провалов: 0
```

Фикс-точка Windows из `raz/`:

```powershell
cmd /c "разум.exe < разум.раз > сам1.иск"
cmd /c "..\искра.exe < сам1.иск > разум2.exe"
cmd /c "разум2.exe < разум.раз > сам2.иск"
cmd /c "fc /b сам1.иск сам2.иск"
```

Команды Linux/macOS и актуальные платформенные особенности закреплены в
[CI](.github/workflows/ci.yml).

## Порядок разработки

- `main` — стабильная ветка;
- `develop` — рабочая ветка интеграции;
- `фича/<имя>` и `правка/<имя>` создаются от `develop`;
- один независимый этап — один PR;
- после зелёного CI PR вливается в `develop`;
- перенос `develop → main` выполняется отдельным PR;
- код, документация и диагностика внутри проекта пишутся по-русски;
- типовая безопасность не ослабляется ради совместимости старого исходника.
