# Exp_AI_GPU — обучение нейросети на GPU (OpenCL)

Поэтапный перенос `_сегм30м` на GPU через `биб/окл`. Веса и активации живут
в видеопамяти (`CL_MEM_READ_WRITE`), CPU только диспетчеризует запуски ядер;
на хост возвращаются лосс и метрики.

## Этапы

1. **`свертка_замер.раз`** — разведка-замер: OpenCL-ядро свёртки 3×3 по
   float4-блокам против CPU-версии `свертка_пак` из `_сегм30м.раз` на четырёх
   реальных формах сети. Сверка выхода с эталоном (макс. расхождение) и
   замер ускорения.
2. **`форвард_гпу.раз`** — прямой проход `_сегм30м` целиком на GPU:
   6 ядер (conv1, conv, pool2, up2, cat, outm) над двумя аренами
   (веса + тензоры), CPU-эталон на тех же смещениях, послойная сверка
   всех 23 тензоров. `#pragma OPENCL FP_CONTRACT OFF` даёт побайтную
   идентичность.
3. **`визуал_сегм.раз`** — интерактивный прямой проход в окне: U-Net как
   карта слоёв, послойное исполнение по шагам, инспектор каналов.
4. **`обуч_ш5м.раз`** — обратный проход и обучение `_ш5м` целиком на GPU:
   7 ядер (fwd, d3, bwd3, bwd, updw, updb, argm), 13 запусков на пример
   через `окл_поставь` без блокировки, веса/дельты/данные живут в VRAM.
   Поэтапная побитовая сверка первого шага и финальных весов с CPU.

## Запуск (Windows)

```powershell
cmd /c "raz\разум.exe < Exp_AI_GPU\свертка_замер.раз > т_замер.иск"
cmd /c "искра.exe < т_замер.иск > т_замер.exe"
.\т_замер.exe
```

## Результаты

### Этап 1 — свертка_замер (RTX 3070 Laptop, OpenCL, 50 итераций)

| Форма (ш×в, вхб→выхб) | CPU (SSE) | GPU | Ускорение | Макс. расхождение |
|---|---|---|---|---|
| 64×64, 8→8 | ~1900 мс | <1 мс | >x1900 | 0 |
| 32×32, 32→16 | ~4000 мс | 15 мс | ~x253 | 0 |
| 16×16, 64→32 | ~4400 мс | 16 мс | ~x257 | 0 |
| 4×4, 256→256 | ~30200 мс | 62 мс | ~x480 | 0 |

Выход GPU побайтно совпадает с CPU-эталоном (макс_ош = 0.000).
На мелких формах замер упирается в накладные расходы запуска (~20 мкс на
вызов) — реальное ускорение там ещё выше; на самой тяжёлой форме
(4×4, 1024→1024 канала) честные ~x480 на вызов свёртки.

### Визуализация — `визуал_ш5м.раз` (этап UI)

Интерактивная среда обучения сети `_ш5м` (4096→1152→288→8, ~5М параметров)
в окне 1280×800 на `биб/холст` + `биб/окно` + `биб/уй`:

- **Управление**: кнопки ПАУЗА/ШАГ/СБРОС и темп ×1/×4/×16; пробел — пауза,
  стрелка вправо — шаг по одному примеру.
- **Граф сети**: колонки слоёв, нити с цветом/толщиной по весу
  (бирюзовый +, оранжевый −), узлы с размером/яркостью по активации.
- **Инспектор нейрона**: клик по узлу скрытого/выходного слоя → карта
  входных весов («что видит нейрон») и его активация.
- **Метрики**: эпоха, пример, точность, лосс (MSE), примеров/с, кадров/с,
  время работы.
- **Пространство вероятностей**: теплокарта 64 последних примеров × 8
  классов; кривая точности по времени (600 точек).

```powershell
cmd /c "raz\разум.exe < Exp_AI_GPU\визуал_ш5м.раз > т_виз.иск"
cmd /c "искра.exe < т_виз.иск > т_виз.exe"
.\т_виз.exe
```

### Этап 2 — форвард_гпу (RTX 3070 Laptop, одна сцена 64×64)

Полный прямой проход `_сегм30м`: 38 запусков ядер, веса в VRAM (~124 МБ
арена), тензоры в общей арене (~8 МБ). Паттерн: смещения `о_*` общие для
CPU-эталона и GPU-цепочки — слои сравниваются по одним индексам.

| Проход | Время |
|---|---|
| CPU (SSE, РАЗУМ) | 1391 мс |
| GPU (OpenCL) | 15 мс |
| **Ускорение** | **~x87** |

Все 23 проверенных тензора совпали **побайтно** (макс_ош = 0.000),
включая выход с сигмоидой — `#pragma OPENCL FP_CONTRACT OFF` запрещает
слияние в FMA, иначе последние биты разошлись бы.

Найдено свойство языка: `указатель + n` — **байтовая** арифметика, а не
по элементам (в отличие от `указатель[n]`). Для смещений в арене —
хелпер `ар()` через `*нат.старт`.

```powershell
cmd /c "raz\разум.exe < Exp_AI_GPU\форвард_гпу.раз > т_форв.иск"
cmd /c "искра.exe < т_форв.иск > т_форв.exe"
.\т_форв.exe
```

### Визуализация — `визуал_сегм.раз` (этап 2.5, UI над GPU)

Интерактивный прямой проход `_сегм30м` в окне 1280×860. Вся цепочка
считается в VRAM; на CPU раз в кадр читается арена тензоров (~8 МБ)
только для отрисовки — ~36–52 кадр/с.

- **Карта сети**: энкодер слева сверху вниз (ВХОД → пр6б), декодер справа
  снизу вверх (вверх5 → ВЫХОД); skip-связи U-Net — горизонтальные нити
  между колонками; узел = подпись + ряд из 8 плиток карт признаков
  (тепловая палитра активаций). Неготовые слои приглушены, последний
  выполненный подсвечен.
- **Управление**: АВТО (пробел) — непрерывный проход, СЛОЙ (стрелка
  вправо) — один слой за раз, СЦЕНА — новый вход и сброс, темп ×1/×4/×8.
- **Инспектор**: клик по узлу → сетка до 32 каналов слоя крупно
  (8×4 по 64px), статистика мин/макс/сред; у входа — сцена 64×64,
  у выхода — 4 маски + цветное наложение.
- **Шкала времени**: внизу 38 столбиков — мс на слой; на RTX 3070
  полный проход ~15 мс, из них ~14 мс — слой 16 (пр6б, 2×2, 256→256
  блоков).
- **Табличная диспетчеризация**: слой описан строкой
  (вид, офс_вх, офс_вых, офс_весов, офс_смещ, ш, в, вхб, выхб) —
  задел под декларативную среду «слой → ЦПУ/ГПУ».

```powershell
cmd /c "raz\разум.exe < Exp_AI_GPU\визуал_сегм.раз > т_сегм.иск"
cmd /c "искра.exe < т_сегм.иск > т_сегм.exe"
.\т_сегм.exe
```

### Этап 3 — обуч_ш5м (RTX 3070 Laptop, обучение на GPU)

Полный цикл обучения `_ш5м` (4096→1152→288→8, ~5.05М весов, SGD по одному
примеру) в видеопамяти: на пример — fwd×3, argm, d3, bwd3, bwd,
updw/updb×3; на эпоху — 6240 постановок и одно чтение флагов точности.

| Эпоха | CPU | GPU |
|---|---|---|
| время | ~2300 мс | ~400 мс (**~x6**) |
| верно | 197→355→427→447→465→465 | идентично |

Побитовая идентичность с CPU: поэтапная сверка примера 0 (акк, ш1, ш2,
вых, д3, д2, д1, обновлённые веса — 0 различий) и финальные веса после
6 эпох — **0 различий из 5 054 120 float**.

Два нетривиальных условия побитового совпадения:

- **порядок сумм**: `сумма` на CPU — попарная `(x+y)+(z+w)`; дельта
  `д2` у CPU — `сумма(w0·д0 + w1·д1)`, а не `сумма+сумма` → отдельное
  ядро `bwd3` с точным порядком;
- **деление**: у NVIDIA float-деление `/` не корректно округлённое
  (нет `CL_FP_CORRECTLY_ROUNDED_DIVIDE_SQRT`) → в сигмоиде литеральные
  `1.f/n`, `se=1.f+s` во float (как у CPU), само деление — через
  `convert_double4`/`convert_float4` (fp64-деление корректно округлённое).

```powershell
cmd /c "raz\разум.exe < Exp_AI_GPU\обуч_ш5м.раз > т_обуч.иск"
cmd /c "искра.exe < т_обуч.иск > т_обуч.exe"
.\т_обуч.exe
```

### Этап E — обуч_ош: классификатор вида ошибки (корпус-2 → GPU)

Первый ML-слой «мозга редактора». Данные — `raz/корпус.tsv` +
`корпус_мут_<ид>.раз` (генератор `raz/корпус.раз`). Задача: по строке
кода и тексту диагностики предсказать вид мутации — 9 классов
(8 видов + «чисто»); «чисто» = фаза «нет» (мутант компилируется).

Признаки 4096 (бинарные): байтовые триграммы → 2048 бинов, FNV-хеши слов
→ 2048 бинов, длина слова % 64 → младшие бины. Сеть та же, что `_ш5м`
(4096→1152→288→12, сигмоида, MSE, SGD) — выходной слой расширен до 3
блоков f4 (ядро `bwd3o`, `argm` по 9 классам). Размер корпуса и сплит
вычисляются из TSV: каждый 5-й ряд → тест.

Запуск из `raz/` (там корпус): `../Exp_AI_GPU/обуч_ош.exe`.

Корпус-2 масштабирован: `корпус.exe цели.txt N зерно старт` — своё зерно
и смещение ид для параллельных прогонов (TSV пишется в
`корпус_<старт>.tsv`). 6 прогонов по 95 файлам × 75 мутантов =
**42750 примеров**, баланс ~5300/вид + 6439 «чистых».

Результат v2 (60 эпох, ~33 с/эпоха, побитовая сверка — 0 разл.):

- обучение 90.3%, **тест 70.4%** (6017/8550) при случайных ~11%;
- по видам на тесте: строка 79%, дублировать 78%, вставить 75%,
  укоротить 67%, заменить 65%, обмен 60%, удалить 52%, имя 50%,
  чисто ~100%;
- путаница логична: `дублировать`/`имя`/`укоротить` делят диагностику
  «неизвестное имя X» — дальше признаки формы имени, контекст строк,
  softmax+CE вместо MSE.

Результат v1 (1400 примеров, 7 файлов): обучение 74.7%, тест 27.9%.

### Инференс в редакторе — ош_инф

`обуч_ош.exe` в конце обучения выгружает веса в `ош_веса.bin`
(арена float4, 1263819·16 байт). `ош_инф.раз` — CPU-инференс той же
сети: читает веса, кодирует пример теми же признаками, прогоняет
прямой проход (один пример — миллисекунды, GPU не нужен).

```text
stdin:  строка кода\nтекст диагностики\n
argv:   ош_инф.exe [путь_к_весам.bin]   (умолчание ош_веса.bin в cwd)
stdout: вид <имя>
        оценки <9 чисел 0..1>
```

Расширение VS Code (0.4) вызывает его на первой ошибке разума и
дописывает `[ML: <вид>]` к диагностике; команда «ВЕЛЕС: угадать вид
ошибки (ML)» — для диагностики у курсора. Настройки `veles.mlPath` /
`veles.mlWeights` переопределяют пути.
