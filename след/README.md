# СЛЕД — отладчик ВЕЛЕС

Интерактивный машинный отладчик для программ экосистемы ВЕЛЕС (и вообще
любых PE64-программ Windows x64), написанный на **РАЗУМЕ** поверх
Win32 Debug API.

Отлаживает всё, что производит цепочка `разум → искра`, включая
сам компилятор `raz/разум.exe` и ассемблер `искра.exe`.

Подтверждённые дефекты и порядок развития ведутся в
[ЗАДАЧИ.md](ЗАДАЧИ.md). Общая очередь ВЕЛЕСА — в
[../ЗАДАЧИ.md](../ЗАДАЧИ.md). Критические задачи жизненного цикла процесса
ещё не закрыты, поэтому наличие базового вертикального среза не означает
завершённость отладчика.

## Сборка

Из каталога `след/` (модули `взять` подхватываются из `../биб/`):

```powershell
cmd /c "..\raz\разум.exe < след.раз > след.иск"
cmd /c "..\искра.exe < след.иск > след.exe"
```

## Запуск

```
след.exe [цель.exe]
```

Цель можно передать аргументом или запустить командой `пуск` внутри.

## Команды

| Команда | Действие |
|---------|----------|
| `пуск <exe>` | запустить процесс под отладкой (стоп на входе) |
| `вход` | точка останова на точке входа образа |
| `б А` / `точка А` | точка останова: `0xАДР`, `HEX`, символ, регистр, `сим+0xсмещ` |
| `сними N\|А` | снять точку по номеру, адресу или имени |
| `точки` | список точек с именами символов |
| `иди` / `д` | продолжить до останова |
| `шаг [n]` / `ш` | n инструкций (TF, по умолчанию 1) |
| `до А` | бежать до адреса (временная точка) |
| `возврат` | выйти из функции — бежать до `[укс]` |
| `наблюд А` | аппаратная точка на запись 8 байт (DR0) |
| `наблюд-` | снять точку наблюдения |
| `реги` / `р` | все регистры + EFlags |
| `уст Р V` | записать hex-значение в регистр |
| `пам А [n]` / `м` | hex+ASCII дамп n байт (по умолч. 128) |
| `стек [n]` | n слов стека с именами символов |
| `карта ф.иск` | построить карту символов по исходной ИСКРЕ |
| `символы` | список символов |
| `инфо` | пид, база, вход, счётчики |
| `стоп` / `отцепи` | убить процесс / отпустить |
| `выход` | завершить отладчик |

Везде `А` = `0xHEX | HEX | имя_символа | регистр`, допускается `±0xсмещ`.

## Карта символов

Отладочной информации в PE нет, поэтому `карта` строит символы эвристикой:
метки из исходного `.иск`, за которыми идёт пролог `ВСТЕК УКК /
ПЕР УКК, УКС`, сопоставляются по порядку с байтами `55 48 8B EC`
в секции `.text` (валидный пролог — в начале секции или сразу за
`C3`/`C9`/`CC`/`90`). Точка входа добавляется как `старт`.

Работает для кода, сгенерированного РАЗУМОМ. Если число прологов
и меток разошлось — карта частичная, отладчик честно сообщает.

## Архитектура

| Файл | Назначение |
|------|------------|
| `ипп.раз` | Win32 Debug API, константы, раскладка `CONTEXT`/`DEBUG_EVENT` (x64) |
| `ядро.раз` | состояние, запуск, цикл событий, точки int3, шаги, DR0-наблюдение |
| `пе.раз` | разбор PE64: вход, секции, эвристическая карта символов |
| `след.раз` | интерфейс командной строки |

## Особенности реализации

- Программные точки — `0xCC` с сохранением оригинального байта;
  при останове байт возвращается, `сч` откатывается на адрес точки,
  при продолжении — шаг через восстановленный байт и повторное
  вооружение. Снятие точки, стоящей «на вооружении после шага»,
  корректно сбрасывает отложенный возврат.
- Системный int3 загрузчика (`ntdll`) проглатывается молча.
- Точка наблюдения — DR0/DR7 (L0, запись, 8 байт), распознаётся
  по битам DR6 на `EXCEPTION_SINGLE_STEP`.
- Все события продолжаются корректным статусом (`DBG_CONTINUE` /
  `DBG_EXCEPTION_NOT_HANDLED`), хендлы файлов из событий закрываются.

## Ограничения

- Только Windows x64, только native-процессы.
- Символы — эвристика по `.иск`, без типов и номеров строк
  (для полноценных имён нужен debug-формат — в роадмапе компилятора).
- Один аппаратный watchpoint (DR0).
- Нет дизассемблера — показываются сырые байты по `сч`.
