# ВЕЛЕС — памятка для новой сессии

Этот файл — обязательная точка входа перед любыми изменениями. Он фиксирует
фактическое состояние проекта, ближайшую задачу и правила работы. Подробности:
[README.md](README.md), [ROADMAP.md](ROADMAP.md), [ЗАДАЧИ.md](ЗАДАЧИ.md),
[канон](docs/05-канон.md).

## Что такое ВЕЛЕС

ВЕЛЕС — самостоятельная русскоязычная экосистема нативного программирования:

```text
ИСКРА → РАЗУМ → ЯР
   └──── СЛЕД ────┘
```

- **ИСКРА** — русский ассемблер x86-64 и эмиттер PE64, ELF64, Mach-O.
- **РАЗУМ** — статический системный язык уровня C, компилируемый в ИСКРУ.
- **ЯР** — будущий язык высокого уровня; пока существует как черновая спецификация.
- **СЛЕД** — машинный отладчик PE64/Windows x64, написанный на РАЗУМЕ.

Это не виртуальная машина. Конечный результат — настоящий машинный код. Python
использовался только как ранние строительные леса и не является частью текущей
цепочки сборки.

## Фактическое состояние

- ИСКРА и РАЗУМ написаны на РАЗУМЕ и самодостаточны.
- Поддерживаются Windows x64, Linux x64 и macOS x86-64.
- В репозитории лежат шесть нативных сидов:
  `искра.exe`, `искра`, `искра_мак`, `raz/разум.exe`, `raz/разум`,
  `raz/разум_мак`.
- CI на трёх ОС проверяет нативный прогон и фикс-точку самосборки.
- Нативный прогон после введения строгого `лог`: 24/24.
- Строгий `лог` уже реализован и слит в `main`: условия и `не`/`и`/`или`
  принимают только `лог`, значения нормализуются до `нет`/`да`, `как лог`
  для чисел и указателей запрещено.
- Ось безопасности `--режим надёжно|быстро` реализована: `надёжно` по
  умолчанию, режим хранится в `Ген` и испускается прагмой `;режим` в
  ИСКРЕ; неизвестное значение — ошибка с кодом 2.
- Границы массивов `Т[N]` реализованы: известный индекс вне границ —
  статическая ошибка в обоих режимах; в `надёжно` динамическая проверка
  до умножения на размер элемента, сбой → `стд_сбой_границы`, код 101;
  в `быстро` динамическая проверка не генерируется.
- Границы срезов `[]Т` реализованы: индексация по длине (101), создание
  `[a..b]`/`[a..=b]` проверяет знак, порядок и верхнюю границу до арифметики
  длины (102); пустые срезы допустимы; срез сырого указателя предупреждает.
- Границы строк `стр` реализованы: байтовая индексация по длине UTF-8 (101),
  индекс `длина` и пустая строка запрещены; `стр_срез` проверяет диапазон
  всегда (102) — `биб/стр.раз` берёт `система`, цикл отсекается загрузчиком.
- В каноне уже зафиксированы, но ещё не реализованы: `вещ.*` (включая
  половинные `вещ.шаг`/`вещ.шагм`), векторный `век`, `пик`, домены
  памяти, атомы/ограды и флаг `--отладка` с метаданными типов.
- СЛЕД работает только на Windows x64; его подтверждённые дефекты и план:
  [след/ЗАДАЧИ.md](след/ЗАДАЧИ.md).

## Ближайшая задача

Первый незавершённый этап — отдельный PR **`фича/сбой-границы`**:

1. автоматически доступные `стд_сбой_границы`/`стд_сбой_среза`;
2. стабильные коды 101/102/103 и минимальная диагностика без `консоль`;
3. аварийный путь не выделяет память на всех трёх ОС;
4. архитектура предусматривает файл, строку, индекс, длину и вид операции;
5. СЛЕД останавливается на обработчике — сценарий в `след/ЗАДАЧИ.md` и
   Windows CI.

Полная очередь и критерии этапов находятся в [ЗАДАЧИ.md](ЗАДАЧИ.md).
Каждый этап базовой безопасности выполняется отдельным PR.

## Канонический синтаксис и имена

- Явное объявление: `имя тип = выражение`.
- Вывод типа: `введи имя = выражение`.
- `:=` — только переходная устаревшая форма; не размножать её в новом коде.
- Внутренние имена переменных и функций — понятные русские.
- Однобуквенные латинские имена и неясные сокращения запрещены.
- Каталог стандартной библиотеки — `биб/`.
- Каноническая аббревиатура интерфейса — `ипп`.
- Условия требуют `лог`: писать `число != 0`, `указатель != пусто`.
- Не сравнивать языки ВЕЛЕСА с другими языками в документации проекта.

```text

raz/                 компилятор РАЗУМА
```

Ключевые файлы РАЗУМА:

- `raz/разум.раз` — CLI;
- `raz/загрузчик.раз` — загрузка модулей;
- `raz/лексер.раз`, `raz/парсер.раз` — разбор;
- `raz/ген.раз` — типизация и генерация ИСКРЫ;
- `raz/опт.раз` — пипхол-оптимизация.

## Обязательный порядок работы

1. Начать от актуального `develop`.
2. Создать одну ветку `фича/<задача>` или `правка/<задача>`.
3. Не смешивать независимые этапы в одном PR.
4. Сначала воспроизвести дефект или добавить падающий тест.
5. Проверить самосборку, фикс-точку, ИСКРУ и нативный прогон.
6. Обновить спецификацию, канон, ROADMAP/ЗАДАЧИ и SETUP_LOG.
7. PR в `develop`; после зелёного CI — отдельный PR `develop → main`.
8. Не заявлять о слиянии или успехе CI без результата GitHub.

## Основные проверки

Windows, из корня:

```powershell
cmd /c "raz\разум.exe < тесты\прогон.раз > прогон.иск"
cmd /c "искра.exe < прогон.иск > прогон.exe"
.\прогон.exe
```

Фикс-точка Windows, из `raz/`:

```powershell
cmd /c "разум.exe < разум.раз > сам1.иск"
cmd /c "..\искра.exe < сам1.иск > разум2.exe"
cmd /c "разум2.exe < разум.раз > сам2.иск"
cmd /c "fc /b сам1.иск сам2.иск"
```

Linux и macOS выполняют те же два поколения своими сидами и целями; точные
команды являются исполняемой спецификацией в `.github/workflows/ci.yml`.

## Нельзя забывать

- Не возвращать Python в цепочку сборки.
- Не ослаблять типовую безопасность ради старого исходного кода.
- `-O0/-O1` и `--режим надёжно|быстро` — независимые оси.
- Сырой указатель не содержит длину: будущий надёжный режим не должен создавать
  ложное впечатление проверенной границы.
- Изменения форматов, типов машинного размера, владения строками и интерфейсов
  модулей — отдельные архитектурные PR, а не побочные правки кодогенератора.
