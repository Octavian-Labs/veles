# Канон стиля языков ВЕЛЕС

Дата: 2026-09-20

## Назначение

Этот документ фиксирует канон стиля для экосистемы ВЕЛЕС:

- ИСКРА — низкий уровень, строгий и компактный.
- РАЗУМ — системный уровень, ясный и минималистичный.
- ЯР — верхний уровень, плавный и естественный.

Главный принцип: вся экосистема должна говорить по-русски не только в
ключевых словах, но и в именах, модулях, служебных обозначениях
и документации.

## Общие принципы

### 1. Только русские имена

Во всей экосистеме запрещаются английские внутренние названия вроде:

- runtime
- stdlib
- backend
- frontend
- toolchain
- helper
- utils

Используются только русские эквиваленты:

| Нежелательно | Канонично |
|---|---|
| runtime | среда_исполнения |
| stdlib | стандартная_библиотека |
| backend | кодогенератор / нижний_уровень |
| frontend | разбор / синтаксический_разбор |
| toolchain | цепочка_сборки |
| helper | служебная_функция |
| utils | утилиты / служебное |

### 2. Минимум знаков

Синтаксис должен использовать как можно меньше специальных символов.

- Один символ лучше двух.
- Короткий оператор лучше длинного.
- Скобки допустимы только там, где без них ухудшается точность.
- Новые операторы добавляются только при реальной необходимости.
- Безопасность важнее экономии символов: опечатка должна быть ошибкой
  компилятора, а не новой сущностью.

### 3. Один смысл — одно написание

Если конструкция уже существует, не вводится второй способ сделать то же
самое.

Плохо:

- `:=` и `=` одновременно как равноправные формы.
- `верни` и `дай` в одном языке без причины.
- `строка.склей(а, б)` и `а.склей(б)` одновременно как равноправные формы.

Хорошо:

- один канонический способ;
- при необходимости второй путь существует только как внутренний
  или переходный.

Единственное разрешённое исключение — `РАВНО` в ИСКРЕ (см. канон ИСКРЫ).

### 4. Уровни различаются характером

| Язык | Характер | Принцип |
|---|---|---|
| ИСКРА | резкий, короткий, технический | близко к железу |
| РАЗУМ | строгий, ясный, системный | минимум магии |
| ЯР | плавный, живой, выразительный | код как речь |

### 5. Правило числа

Во всей экосистеме по умолчанию используется **единственное число**.

Это относится к:

- модулям;
- пространствам имён;
- типам;
- базовым сущностям;
- стандартной библиотеке;
- системным подсистемам.

Примеры:

```text
система.файл
система.память
система.процесс
строка
список
ошибка
```

Множественное число используется только там, где сущность действительно
обозначает набор или коллекцию.

Примеры:

```text
файлы
строки
списки
процессы
аргументы
ошибки
```

Главное различие:

- `файл` — одна сущность или модуль работы с файлом;
- `файлы` — набор файлов.

## Канон ИСКРЫ

## Цель

ИСКРА не должна быть разговорной. Это не «красивый русский текст», а
компактный язык управления машиной.

Главные качества ИСКРЫ:

- краткость;
- закономерность;
- визуальная строгость;
- отсутствие лишних синонимов.

## Оформление

### Регистр

- Директивы — ВЕРХНИМ РЕГИСТРОМ.
- Мнемоники — ВЕРХНИМ РЕГИСТРОМ.
- Регистры — ВЕРХНИМ РЕГИСТРОМ.
- Метки, имена функций, имена данных — нижним регистром.

Пример:

```asm
СЕКЦИЯ код
ВХОД старт

ф_главная:
    ПЕР АКК, 0
    ВОЗВРАТ
```

### Отступы

- Метка без отступа.
- Инструкция — 4 пробела.
- Один оператор на строку.
- Один пробел после мнемоники.
- Один пробел после запятой.

Пример:

```asm
м_цикл_начало:
    СРАВ АКК, СЧТ
    РАВНО м_цикл_конец
    ДОБ АКК, 1
    ПРЫГ м_цикл_начало
```

### Комментарии

- Комментарий начинается с `;`.
- Перед комментарием у инструкции — не менее двух пробелов.
- Комментарии пишутся кратко и по делу.

Пример:

```asm
ПЕР АКК, 0      ; код возврата
```

## Именование

### Канонические префиксы

| Категория | Канон | Пример |
|---|---|---|
| Функция | `ф_` | `ф_главная`, `ф_печать` |
| Стандартная библиотека | `стд_` | `стд_выдели`, `стд_освободи` |
| Служебная функция | `служ_` | `служ_проверка_границ` |
| Системная функция | `сист_` | `сист_выход`, `сист_чтение` |
| Метка | `м_` | `м_цикл_начало`, `м_выход` |
| Данные строки | `стрд_` | `стрд_ошибка` |
| Строковый объект | `стр_` | `стр_ошибка` |
| Константа | `КОНСТ_` | `КОНСТ_БУФЕР` |

### Правило числа в ИСКРЕ

- Имя функции, модуля и сущности — в единственном числе.
- Множественное число — только если имя обозначает список, набор
  или таблицу.

Хорошо:

```text
ф_файл_прочти
ф_строка_найди
КОНСТ_РАЗМЕР_БУФЕРА
```

Допустимо для коллекций:

```text
таблица_символов
аргументы
ошибки
```

### Правила для меток

Метка должна отвечать на вопрос «что это за место?», а не «какой это
номер?».

Плохо:

```asm
м2_пока:
м63_есликон:
```

Хорошо:

```asm
м_чтение_цикл_начало:
м_чтение_цикл_конец:
м_ошибка_записи:
м_главная_выход:
```

Если нужен номер для уникальности, он ставится в конце:

```asm
м_разбор_цикл_начало_1:
м_разбор_цикл_конец_1:
```

### Метки кодогенератора

Компилятор РАЗУМА генерирует метки по тому же канону — имя функции,
контекст и номер в конце:

```asm
м_главная_цикл_начало_2:
м_главная_цикл_конец_2:
м_главная_если_конец_3:
м_стр_число_выход:
```

Это не влияет на машинный код, но делает сгенерированную ИСКРУ читаемой
и отлаживаемой.

## Словарь ИСКРЫ

### Оставить и закрепить

| Группа | Мнемоники |
|---|---|
| Перемещение | `ПЕР`, `АДР`, `ОБМЕН` |
| Арифметика | `ДОБ`, `ВЫЧ`, `УМН`, `ДЕЛ`, `ОТР` |
| Логика | `И`, `ИЛИ`, `ИИЛИ`, `НЕ` |
| Сравнение | `СРАВ`, `ПРОВ` |
| Стек | `ВСТЕК`, `ИЗСТЕКА` |
| Вызов | `ВЫЗОВ`, `ВОЗВРАТ`, `ПОКИНЬ` |
| Переход | `ПРЫГ`, `РАВНО`, `НЕРАВНО`, `МЕНЬШЕ`, `БОЛЬШЕ`, `НИЖЕ`, `ВЫШЕ` |
| ОС и машина | `НОП`, `СТОП`, `ПРЕРЫВ`, `СИСВЫЗОВ` |
| Данные | `БАЙТ`, `СЛОВО`, `ДВСЛОВО`, `КВАД`, `РЕЗЕРВ`, `ВЫРОВНЯТЬ` |
| Структура | `СЕКЦИЯ`, `ИМПОРТ`, `ВХОД`, `РАВНО` |

### `РАВНО` — осознанное исключение

`РАВНО` — допустимое контекстное омонимичное слово ИСКРЫ:

```asm
РАЗМЕР_БУФЕРА РАВНО 4096    ; директива определения константы
    РАВНО м_выход           ; переход при равенстве
```

Синтаксические позиции несовместимы: после имени — директива константы,
в позиции инструкции — условный переход. Это единственное разрешённое
исключение из правила «один смысл — одно написание».

### Не делать

- Не вводить разговорные синонимы.
- Не заменять `[]`, `+`, `-`, `*` внутри адресации русскими словами.
- Не вводить несколько названий для одной инструкции.
- Не делать ИСКРУ «человеческой» ценой точности.

## Псевдоинструкции

Чтобы убрать визуальный шум, в ИСКРУ добавлены необязательные
псевдоинструкции.

### Канонический набор

```asm
ВХОДКАДРА 16
ВЫХОДКАДРА
```

Разворачивание:

```asm
ВХОДКАДРА 16
```

эквивалентно:

```asm
ВСТЕК УКК
ПЕР УКК, УКС
ВЫЧ УКС, 16
```

А

```asm
ВЫХОДКАДРА
```

эквивалентно:

```asm
ПОКИНЬ
```

Это не скрывает низкий уровень, а делает рукописный код чище.

```asm
ИМПОРТ "kernel32" ExitProcess

    ВХОДКАДРА 0

старт:

```

## Канон РАЗУМА

## Цель

РАЗУМ должен быть похож на строгий технический русский язык.

Главные качества:

- минимум символов;
- читаемость как у Python;
- строгость как у системного языка;
- отсутствие скрытой магии;
- явная работа с памятью.

## Главный синтаксический принцип

### Отказ от `:=` и строгое `=`

В РАЗУМЕ каноническим оператором записи является обычный знак `=`, а
объявление всегда идёт с типом:

```raz
счёт цел64 = 0            ; новое имя в текущей области
счёт = счёт + 1           ; запись только в уже объявленное имя
```

Правила:

- `имя тип = выражение` — всегда объявление нового имени.
- `имя тип` — объявление без инициализации.
- `имя = выражение` — только присваивание; если имя не объявлено —
  ошибка компилятора. Опечатка не создаёт переменную.
- `:=` — устаревшая переходная форма объявления с выводом типа;
  поддерживается временно, в новом коде не используется.
- Позднее может появиться слово для вывода типа (`пусть счёт = 0`),
  но это отдельное решение, не часть канона сегодня.

Причины:

- `=` проще зрительно;
- неявное объявление через `имя = значение` опасно: опечатка должна
  быть ошибкой, а не новой переменной;
- различие между объявлением и присваиванием делает тип, а не второй
  оператор.

## Правила переменных

### Канонические формы

```raz
счёт цел64 = 0
размер_буфера без64 = 1024
буфер без8[256]
конст ШИРИНА = 10
тип хендл = без64
```

### Семантика

- `имя тип = выражение` — объявление нового имени с явным типом.
- `имя тип` — объявление без инициализации, только где это нужно.
- `имя = выражение` — присваивание существующему имени.
- `конст ИМЯ = выражение` — константа времени компиляции.
- `тип имя = тип` — синоним типа.

### Строгость областей

- Повторное объявление уже существующего имени — ошибка.
- Явное объявление `имя тип` может перекрывать внешнее имя, но такое
  перекрытие видно в тексте и делается осознанно.
- Неявные формы (`:=` переходная, будущий `пусть`) не вправе перекрывать
  уже видимое имя — это ошибка.
- Язык не поощряет случайное затенение.

## Разделители и составные имена

### Каноническое правило

- Точка `.` означает путь к имени: модуль, пространство имён, поле
  или метод.
- Подчёркивание `_` означает единое составное понятие.
- Пробел используется между именем и типом.
- Двоеточие `:` используется для блока.
- Знак `=` используется для связывания и присваивания.

Примеры:

```raz
взять система.файл
взять система.память
код_ошибки цел64 = 0
размер_буфера без64 = 1024
если готово:
    верни 0
```

### Правило числа в РАЗУМЕ

Во всех именах модулей и основных сущностей используется единственное
число.

Хорошо:

```raz
взять система.файл
взять система.память
взять система.процесс
взять строка
взять список
```

Множественное число используется только для коллекций и наборов:

```raz
файлы
строки
процессы
аргументы
ошибки
```

Правило:

- `файл` — модуль или одна сущность;
- `файлы` — набор файлов.

## Скобки и символы

### Канон

- Скобки только там, где они несут смысл.
- Избегать лишней пунктуации.
- Не вводить символический шум ради «строгости».
- Строгость должна обеспечиваться типами, областями видимости
  и семантикой памяти.

Хорошо:

```raz
если длина == 0:
    верни пусто

указ *Запись = новый(Запись)
если (флаги и МАСКА) != 0:
    верни да
```

Плохо:

```raz
если ((длина) == (0)):
    верни(пусто)
```

## Именование в РАЗУМЕ

### Общие правила

- Только русские имена в стандартной библиотеке и служебных сущностях.
- Имена функций — полные и понятные.
- Сокращения допустимы только если они уже очевидны и системны.
- Модули именуются в единственном числе.

### Канонические модули

```text
память
строка
файл
консоль
система
список
основа
ошибка
процесс
```

### Канонические функции

```text
выдели
освободи
скопируй
заполни
равна_память
печать
печатьстр
печатьцел
ввод
выход
строка.склей
строка.равна
строка.срез
строка.найди
строка.в_нуль
строка.в_число
список.новый
список.добавь
список.получи
список.освободи
```

## Точечные модули — целевая модель

Пространства имён через точку — отдельная возможность, реализуется своей
веткой после фиксации семантики переменных.

```raz
взять система.файл
взять строка

текст стр = файл.прочти("вход.txt")
позиция цел64 = строка.найди(текст, "42")
```

Правила:

- `взять система.файл` ищет `lib/система/файл.раз`;
- точка в имени импорта означает путь модуля;
- точка в выражении — доступ к полю, методу или экспортированному
  имени модуля;
- различение делает семантический анализ, не лексер;
- импорт без псевдонима открывает последнее имя пути:
  `система.файл` → `файл`;
- позже допустим псевдоним: `взять система.файл как ф`.

## Стиль API

### Направление развития

Внутри стандартной библиотеки канонический стиль — пространство имён
через точку:

```raz
строка.найди(текст, "42")
строка.срез(текст, 0, 4)
файл.прочти("вход.txt")
память.выдели(256)
```

Для пользовательского кода в дальнейшем допустим мягкий переход
к методам, если реализация будет устойчивой:

```raz
текст.найди("42")
текст.срез(0, 4)
```

Но канон на текущем этапе:

- основной стиль стандартной библиотеки — пространство имён через точку;
- не поддерживать две равноправные публичные формы без необходимости.

## Память и строгость

Строгость РАЗУМА должна идти не от тяжёлого синтаксиса, а от правил
языка.

### Канонические принципы

- Нет GC.
- Нет скрытых аллокаций.
- Нет скрытых копирований.
- Нет неявных преобразований типов.
- Адрес и разыменование явны.
- Работа со строками и срезами предсказуема.

### Документируемые правила

Закреплено отдельно:

- длина строк — в байтах;
- строки UTF-8 не индексируются по символам;
- `строка.в_нуль` создаёт нуль-терминированную копию;
- срез не копирует данные, если явно не сказано иначе;
- ответственность за освобождение памяти должна быть очевидна.

## Пример канонического РАЗУМА

```raz
взять система.файл
взять система.память
взять строка

функ площадь(ширина, высота цел64) цел64:
    верни ширина * высота

функ главная() цел32:
    ширина цел64 = 1920
    высота цел64 = 1080
    площадь_экрана цел64 = площадь(ширина, высота)

    текст стр = файл.прочти("вход.txt")
    буфер *без8 = память.выдели(4096)

    печатьцел(площадь_экрана)
    память.освободи(буфер)
    верни 0
```

## Канон ЯРА

## Цель

ЯР — самый естественный язык экосистемы.

Главные качества:

- код читается как русская речь;
- минимум шума;
- плавные конструкции;
- простота записи повседневной логики.

## Канон выражения

Хорошо:

```yar
если пользователь не пусто:
    печать("Привет, {пользователь}!")
иначе:
    печать("Гость")
```

Хорошо:

```yar
для имя в имена:
    печать(имя)
```

## Что оставить

- `если / а если / иначе`
- `для ... в ...`
- `пока`
- `вечно`
- `дай`
- `хватит`
- `следующий`
- `да / нет / пусто`
- `суть`
- `тут`

## Что вводить осторожно

- `оно` как неявный результат;
- несколько синонимов одной конструкции;
- избыточные разговорные формы;
- слишком много «умных» сокращений;
- одновременная поддержка множества грамматических вариантов.

## Правило числа в ЯРЕ

- Типы, сущности и пространства имён — в единственном числе.
- Коллекции и наборы — во множественном.

Примеры:

```text
Фигура
Игрок
Сообщение
фигуры
игроки
сообщения
```

## Правило ЯРА

ЯР красив только пока программист угадывает синтаксис следующей строки
без чтения справки.

Поэтому:

- меньше магии;
- меньше особых случаев;
- меньше скрытых состояний;
- больше естественного ритма.

## Единый словарь ВЕЛЕСа

| Понятие | ИСКРА | РАЗУМ | ЯР |
|---|---|---|---|
| Истина | флаги / сравнение | `да` | `да` |
| Ложь | флаги / сравнение | `нет` | `нет` |
| Нет значения | — | `пусто` | `пусто` |
| Условие | `РАВНО`, `НЕРАВНО` и др. | `если` | `если` |
| Цикл | `ПРЫГ` + метки | `пока`, `для` | `пока`, `для` |
| Вызов | `ВЫЗОВ` | `функ` / вызов | `умеет` / вызов |
| Возврат | `ВОЗВРАТ` | `верни` | `дай` |
| Память | адреса и регистры | `новый`, `освободи`, `&`, `*` | скрыта средой |

## Правила для разработчика

### Обязательно

- Все системные, стандартные и служебные имена — только на русском.
- Английские имена допустимы только для внешних ABI-символов,
  импортируемых из ОС и библиотек.
- В каждом языке должен быть один основной стиль записи.
- Новая конструкция добавляется только если она сокращает мысль,
  а не просто символы.
- Строгость достигается семантикой, а не визуальным перегрузом.
- По умолчанию используется единственное число для модулей, типов
  и сущностей.

### Запрещается

- Вносить английские внутренние термины в спецификацию и кодогенерацию.
- Поддерживать несколько равноправных синтаксисов без необходимости.
- Добавлять новые операторы ради модности.
- Делать низкий уровень разговорным.
- Делать высокий уровень магическим и непредсказуемым.
- Неявно создавать имена: неизвестное имя слева от `=` — ошибка.

## Короткая формула экосистемы

- ИСКРА — короткая и железная.
- РАЗУМ — строгий и чистый.
- ЯР — плавный и живой.

Если возникает сомнение, как должна выглядеть новая конструкция,
применяется правило:

> меньше знаков, меньше шума, меньше магии, больше русской ясности.
