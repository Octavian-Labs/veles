# ВЕЛЕС — канон имён, типов и стандартной библиотеки

Дата: 2026-09-20 (ред. 2)
Статус: действующий канон экосистемы
Назначение: документ для разработчика, реализующего канон ИСКРЫ, РАЗУМА и будущего ЯРА.

## 1. Общий принцип ВЕЛЕСа

Во всей экосистеме используются только русские имена.

Запрещаются английские внутренние термины:

- runtime
- stdlib
- backend
- frontend
- toolchain
- helper
- utils

Вместо них используются русские формы:

| Нежелательно | Канонично |
|---|---|
| runtime | среда_исполнения |
| stdlib | стандартная_библиотека |
| backend | кодогенератор / нижний_уровень |
| frontend | разбор / синтаксический_разбор |
| toolchain | цепочка_сборки |
| helper | служебная_функция |
| utils | служебное / утилиты |

Английские имена допустимы только для внешних ABI-символов, импортируемых
из операционной системы или чужих библиотек (`CreateProcessW`, `kernel32`).

## 2. Правило числа

Во всей экосистеме по умолчанию используется **единственное число**.

Это относится к:

- модулям;
- пространствам имён;
- типам;
- подсистемам;
- главным сущностям.

Примеры:

```text
сист.файл
сист.пам
сист.проц
стр
список
ошибка
мат
```

Множественное число допустимо только для коллекций, наборов и таблиц:

```text
файлы
строки
аргументы
ошибки
таблица_символов
```

## 3. Правило сокращений

### Основной принцип

Сокращаются:

- корневые пространства имён;
- технические категории;
- часто используемые модульные пути.

Не сокращаются:

- действия;
- предикаты;
- ключевые смысловые слова API.

### Правильный стиль

```raz
мат.вещ.округли(число)
мат.цел.это_простое(число)
сист.файл.прочти("вход.txt")
сист.пам.освободи(буфер)
стр.найди(текст, "ошибка")
конс.печатьстр("Готово")
```

### Неправильный стиль

```raz
математика.вещественное.окр(число)
система.память.осв(буфер)
строка.нйд(текст, "ошибка")
```

### Каноническое правило

> Сокращается только путь. Не сокращается действие.

| Полное понятие | Канон |
|---|---|
| математика | `мат` |
| система | `сист` |
| вещественная математика | `вещ` |
| целочисленная математика | `цел` |
| натуральная арифметика | `нат` |
| строка | `стр` |
| память | `пам` |
| файл | `файл` |
| консоль | `конс` |
| процесс | `проц` |
| ошибка | `ош` |
| список | `список` |
| время | `время` |

Примеры:

```raz
взять мат
взять стр
взять сист.файл
взять сист.пам
взять конс
```

## 5. Разделители

### Каноническое правило

- Точка `.` — путь, пространство имён, подмодуль, поле, метод, уровень типа.
- Подчёркивание `_` — единое составное понятие.
- Пробел — разделение имени и типа.
- Двоеточие `:` — начало блока.
- Равно `=` — связывание или присваивание.

### Примеры

```raz
взять сист.файл
код_ошибки цел.рост = -1
если готово:
    верни 0
```

## 6. Канон типов РАЗУМА

### Основной принцип

Старые формы типа:

```text
цел64
без64
цел32
без32
бул
```

считаются устаревшими и подлежат замене. В переходный период они читаются
компилятором как синонимы, но в новом коде не употребляются.

Причины замены:

- цифры визуально шумят;
- `без64` может читаться как операция «без 64»;
- типы должны звучать как имена сущностей, а не как фрагменты формулы.

### Семейства

| Семейство | Назначение |
|---|---|
| `цел` | целое со знаком |
| `нат` | натуральное / беззнаковое целое |
| `вещ` | вещественное |
| `лог` | логическое |
| `сим` | одиночный байт / символ |
| `пусто` | отсутствие значения |

### Уровни

| Уровень | Разрядность | Байты |
|---|---:|---:|
| `старт` | 8 | 1 |
| `шаг` | 16 | 2 |
| `рост` | 32 | 4 |
| `верх` | 64 | 8 |
| `пик` | 128 | 16 |

### Канонические типы

```text
цел.старт
цел.шаг
цел.рост
цел.верх

нат.старт
нат.шаг
нат.рост
нат.верх

вещ.рост
вещ.верх

лог
сим
пусто
стр
```

### Примеры

```raz
код_ошибки цел.рост = -1
размер_файла нат.верх = 4096
символ сим = 65
готово лог = да
точность вещ.верх = 3.1415926535
```

### Замечания для реализации

1. Типы вида `цел.верх` используют точку. В синтаксической позиции типа
   точка читается как часть составного имени типа; в позиции выражения —
   как доступ к полю, модулю или методу. Различение делает парсер по
   контексту позиции.

2. `вещ.*` и уровень `пик` (128 бит) — целевые имена канона. Аппаратной и
   кодогенерационной поддержки плавающей точки и 128-битных целых пока нет:
   компилятор принимает имя синтаксически, но выдаёт ошибку
   «пока не реализовано». Реализация — отдельная веха.

3. Имя `стр` — и тип строки, и пространство имён строковых функций.
   Разрешение контекстное: в позиции типа `стр` — тип; в позиции
   выражения `стр.найди` — модуль. То же для `список` и имён записей:
   переменная всегда побеждает модульное имя.

4. Голые `цел`, `нат`, `вещ` без уровня — не типы. Компилятор сообщает
   «тип требует уровень: цел.верх / нат.рост / …».

## 7. Семантика объявления и присваивания

Оператор `:=` удалён из канона. В переходный период он ещё читается
компилятором с предупреждением об устаревании и не может перекрывать
существующие имена; затем будет убран полностью.

### Базовое правило

```raz
имя тип = выражение
```

— это явное объявление нового имени в текущей области.

```raz
имя = выражение
```

— это присваивание уже существующему имени.

### Примеры

```raz
счёт цел.верх = 0
счёт = счёт + 1

размер нат.верх = 4096
размер = размер + 1
```

### Требования к реализации

- присваивание необъявленному имени — ошибка компиляции;
- опечатка в имени — ошибка, а не создание новой переменной;
- повторное объявление имени в области — ошибка;
- скрытое затенение не допускается без отдельного явного механизма;
- вывод типа при объявлении, если понадобится, вводится отдельной
  конструкцией (например, `пусть имя = выражение`) — не через голое `=`.

## 8. Модули и пространства имён

### Импорт

```raz
взять сист.файл
взять стр
```

- Точка в имени импорта — путь модуля: `сист.файл` → `lib/сист/файл.раз`.
- Поиск идёт по тем же базам, что и для плоских имён (каталог исходника,
  `lib/`, `../lib/`), с учётом целевого суффикса `.windows`/`.linux`.
- Импорт без псевдонима открывает последнее имя пути:
  `взять сист.файл` открывает `файл`.
- Полный путь тоже работает: `сист.файл.прочти(...)`.
- Позже допустим псевдоним: `взять сист.файл как ф`.

### Обращение в выражениях

```raz
текст стр = файл.прочти("вход.txt")
позиция цел.верх = стр.найди(текст, "42")
общий нат.верх = мат.цел.нод(а, б)
```

Правила разрешения `a.b.c` в позиции выражения:

1. Если `a` — локальная переменная или параметр, это доступ к полю/методу.
2. Иначе ищется самый длинный зарегистрированный модульный префикс
   (`мат.цел`, `сист.файл`, `файл`); остаток склеивается в имя
   `префикс_остаток` (`мат.цел.нод` → `цел_нод`, `файл.прочти` → `файл_прочти`).
3. Затем — прямое склеивание всей цепочки (`a_b_c`).
4. Затем, для двухчленной цепочки по открытому модулю — голое имя
   (`конс.печать` → `печать`, переходная мера для библиотек без префикса).
5. Ничего не найдено — обычная ошибка «нет поля / неизвестное имя».

Тем же правилом резолвятся модульные константы (`мат.вещ.ПИ` → `вещ_ПИ`)
и функции как значения.

## 9. Канон стандартной библиотеки РАЗУМА

### Общий стиль

- Модульное пространство имён — короткое.
- Действие — полное слово.
- Смысловые функции не сокращаются.
- Коллекции называются во множественном числе, только если это
  действительно набор.

### Базовые пространства имён

```text
мат
стр
список
конс
сист.файл
сист.пам
сист.проц
сист.ош
```

### Математическая библиотека

```raz
мат.цел.*
мат.нат.*
мат.вещ.*
```

Целочисленная:

```raz
мат.цел.модуль(число)
мат.цел.минимум(а, б)
мат.цел.максимум(а, б)
мат.цел.ограничь(число, низ, верх)
мат.цел.знак(число)
мат.цел.степень(основание, показатель)
мат.цел.корень(число)
мат.цел.нод(а, б)
мат.цел.нок(а, б)
мат.цел.делится(число, делитель)
мат.цел.это_простое(число)
мат.цел.следующее_простое(число)
мат.цел.это_степень_двойки(число)
```

Натуральная:

```raz
мат.нат.минимум(а, б)
мат.нат.максимум(а, б)
мат.нат.ограничь(число, низ, верх)
мат.нат.степень(основание, показатель)
мат.нат.корень(число)
мат.нат.нод(а, б)
мат.нат.нок(а, б)
мат.нат.это_степень_двойки(число)
```

Вещественная (после появления `вещ.*`):

```raz
мат.вещ.модуль(число)
мат.вещ.минимум(а, б)
мат.вещ.максимум(а, б)
мат.вещ.ограничь(число, низ, верх)
мат.вещ.округли(число)
мат.вещ.пол(число)
мат.вещ.потолок(число)
мат.вещ.корень(число)
мат.вещ.степень(основание, показатель)
мат.вещ.синус(угол)
мат.вещ.косинус(угол)
мат.вещ.тангенс(угол)
мат.вещ.логарифм(число)
мат.вещ.экспонента(число)
```

Константы:

```raz
мат.вещ.ПИ
мат.вещ.Е
мат.вещ.ТАУ
```

### Примеры

```raz
взять мат
взять конс

функ главная() цел.рост:
    число цел.верх = -42
    конс.печатьцел(мат.цел.модуль(число))
    верни 0
```

```raz
взять мат

функ главная() цел.рост:
    а нат.верх = 84
    б нат.верх = 126
    результат нат.верх = мат.нат.нод(а, б)
    конс.печатьцел(результат)
    верни 0
```

## 10. Канон ИСКРЫ

### Общие правила

- ИСКРА остаётся короткой и строгой.
- Мнемоники, директивы и регистры — ВЕРХНИМ РЕГИСТРОМ.
- Метки и имена функций — в нижнем регистре.
- Используются только русские служебные имена.

### Префиксы

| Категория | Канон |
|---|---|
| Функция | `ф_` |
| Метка | `м_` |
| Стандартная библиотека | `стд_` |
| Служебное | `служ_` |
| Системное | `сист_` |
| Данные строки | `стрд_` |
| Строковый объект | `стр_` |
| Константа | `КОНСТ_` |

### Метки генератора

Старый стиль вида `м2_пока`, `м63_есликон` неканоничен.

Канон (контекст функции + роль + номер):

```text
м_главная_цикл_начало_1
м_главная_цикл_конец_1
м_разбор_если_конец_2
м_стр_число_выход
```

### Псевдоинструкции

```asm
ВХОДКАДРА 16
ВЫХОДКАДРА
```

Развёртывание:

```asm
ВХОДКАДРА 16   →   ВСТЕК УКК / ПЕР УКК, УКС / ВЫЧ УКС, 16
ВЫХОДКАДРА     →   ПОКИНЬ
```

### Исключение

Слово `РАВНО` допускается в двух ролях:

- после имени — директива определения константы (`РАЗМЕР_БУФЕРА РАВНО 4096`);
- в позиции инструкции — условный переход при равенстве (`РАВНО м_выход`).

Это единственное осознанное контекстное исключение из правила
«один смысл — одно написание».

## 11. Статус внедрения

Реализовано:

- строгое `=` и явное объявление `имя тип = выражение`;
- `:=` — переходная форма с предупреждением, без перекрытия имён;
- метки генератора `м_<функция>_<контекст>_<номер>`;
- псевдоинструкции `ВХОДКАДРА` / `ВЫХОДКАДРА`;
- точечные типы `цел.*`, `нат.*`, `лог` (старые формы — синонимы);
- точечные пути в `взять` и квалифицированные обращения `модуль.имя`.

Отдельными ветками:

- `вещ.*`, `пик` — с появлением кодогенерации плавающей точки;
- полная перестройка `lib/` под канонические пути и имена;
- псевдонимы импорта `взять … как …`;
- методный стиль поверх модульного (`текст.найди("ошибка")`);
- снятие переходных синонимов (`:=`, `цел64`, `бул`, …).

## 12. Короткая формула канона

- Сокращается путь, не сокращается действие.
- По умолчанию — единственное число.
- Типы описываются через семейство и уровень.
- Объявление всегда явное; `=` только пишет в существующее имя.
- РАЗУМ остаётся строгим, но без визуального мусора.
- ИСКРА остаётся короткой и железной.
- Всё внутреннее именование — только на русском.
