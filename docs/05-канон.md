# ВЕЛЕС — канон имён, типов и стандартной библиотеки

Дата: 2026-09-21 (ред. 4)
Статус: действующий канон экосистемы
Назначение: документ для разработчика, реализующего канон ИСКРЫ, РАЗУМА и будущего ЯРА.

## 1. Общий принцип ВЕЛЕСа

Во всей экосистеме используются только русские имена.

Запрещаются английские внутренние термины:

- runtime
- stdlib
- backend
- frontend
- toolchain
- helper
- utils
- api
- lib

Вместо них используются русские формы:

| Нежелательно | Канонично |
|---|---|
| runtime | среда_исполнения |
| stdlib | стандартная_библиотека |
| backend | кодогенератор / нижний_уровень |
| frontend | разбор / синтаксический_разбор |
| toolchain | цепочка_сборки |
| helper | служебная_функция |
| api | ипп (интерфейс прикладного программирования) |
| lib (каталог) | биб |
| utils | служебное / утилиты |

Английские имена допустимы только для внешних ABI-символов, импортируемых
из операционной системы или чужих библиотек (`CreateProcessW`, `kernel32`).

## 2. Правило числа

Во всей экосистеме по умолчанию используется **единственное число**.

Это относится к:

- модулям;
- пространствам имён;
- типам;
- подсистемам;
- главным сущностям.

Примеры:

```text
сист.файл
сист.пам
сист.проц
стр
список
ошибка
мат
```

Множественное число допустимо только для коллекций, наборов и таблиц:

```text
файлы
строки
аргументы
ошибки
таблица_символов
```

## 3. Правило сокращений

### Основной принцип

Сокращаются:

- корневые пространства имён;
- технические категории;
- часто используемые модульные пути.

Не сокращаются:

- действия;
- предикаты;
- ключевые смысловые слова ипп.

### Правильный стиль

```raz
мат.вещ.округли(число)
мат.цел.это_простое(число)
сист.файл.прочти("вход.txt")
сист.пам.освободи(буфер)
стр.найди(текст, "ошибка")
конс.печатьстр("Готово")
```

### Неправильный стиль

```raz
математика.вещественное.окр(число)
система.память.осв(буфер)
строка.нйд(текст, "ошибка")
```

### Каноническое правило

> Сокращается только путь. Не сокращается действие.

## 4. Канонические пространства имён

| Полное понятие | Канон |
|---|---|
| математика | `мат` |
| система | `сист` |
| вещественная математика | `вещ` |
| целочисленная математика | `цел` |
| натуральная арифметика | `нат` |
| строка | `стр` |
| память | `пам` |
| файл | `файл` |
| консоль | `конс` |
| процесс | `проц` |
| ошибка | `ош` |
| список | `список` |
| время | `время` |
| сеть | `сеть` |
| библиотека (каталог стдлиба) | `биб` |
| интерфейс прикладного программирования | `ипп` |

`биб` — каноническое имя каталога стандартной библиотеки (было `lib`).
`ипп` — канонический термин вместо «API»: лицо модуля наружу. Пример:
«старое ипп» вместо «старый API». Англоязычные служебные имена
(`lib`, `api`, `feature/` в ветках) выводятся из обращения; ветки
называются по-русски: `фича/биб`, `правка/…`.

Примеры:

```raz
взять мат
взять стр
взять сист.файл
взять сист.пам
взять конс
```

## 5. Разделители

### Каноническое правило

- Точка `.` — путь, пространство имён, подмодуль, поле, метод, уровень типа.
- Подчёркивание `_` — единое составное понятие.
- Пробел — разделение имени и типа.
- Двоеточие `:` — начало блока.
- Равно `=` — связывание или присваивание.

### Примеры

```raz
взять сист.файл
код_ошибки цел.рост = -1
если готово:
    верни 0
```

## 6. Канон типов РАЗУМА

### Основной принцип

Старые формы типа:

```text
цел64
без64
цел32
без32
бул
```

считаются устаревшими и подлежат замене. В переходный период они читаются
компилятором как синонимы, но в новом коде не употребляются.

Причины замены:

- цифры визуально шумят;
- `без64` может читаться как операция «без 64»;
- типы должны звучать как имена сущностей, а не как фрагменты формулы.

### Семейства

| Семейство | Назначение |
|---|---|
| `цел` | целое со знаком |
| `нат` | натуральное / беззнаковое целое |
| `вещ` | вещественное |
| `век` | вектор фиксированной ширины (SIMD) |
| `лог` | логическое |
| `сим` | одиночный байт / символ |
| `пусто` | отсутствие значения |

### Уровни

| Уровень | Разрядность | Байты |
|---|---:|---:|
| `старт` | 8 | 1 |
| `шаг` | 16 | 2 |
| `рост` | 32 | 4 |
| `верх` | 64 | 8 |
| `пик` | 128 | 16 |

### Канонические типы

```text
цел.старт
цел.шаг
цел.рост
цел.верх

нат.старт
нат.шаг
нат.рост
нат.верх

вещ.шаг
вещ.шагм
вещ.рост
вещ.верх
вещ.пик

лог
сим
пусто
стр
```

### Машинные слова `размер` и `смещение`

`нат.верх`/`цел.верх` фиксируют разрядность (64 бита). Размерные
величины программы — длины, смещения, счётчики — обязаны следовать за
машинным словом цели, а не за константой. Для них введены два типа без
уровня:

| Тип | Знак | Семантика | На x86-64 |
|---|---|---|---|
| `размер` | без | размеры, длины, вместимости, количества, байтовые позиции, индексы, указатели-как-слова | `нат.верх` |
| `смещение` | со | смещения, разности позиций, результаты «позиция или -1» (ssize-подобные возвраты) | `цел.верх` |

Правило выбора:

- `размер` — беззнаковая величина масштаба машинного слова:
  `длина`, `вмест`, `колво`, `инд`, `поз`, размер файла.
- `смещение` — знаковая величина масштаба машинного слова: смещение
  файла, разность позиций, результат `стр_найди` («позиция или -1»).
- `нат.верх`/`цел.верх` — только там, где нужна именно 64-битная
  сетка: битовые поля форматов (PE/ELF64), произвольные 64-битные
  числа, значения-теги.
- Коды возврата, дескрипторы, хендлы и статусы API — не размеры:
  остаются `цел.верх`/`нат.верх` до появления отдельного типа
  машинных слов-значений.

Текущее состояние реализации: `размер` и `смещение` — ABI-совместимые
синонимы `нат.верх`/`цел.верх` (внутренне `без64`/`цел64`). Поэтому
`размер` свободно заменяет `нат.верх` и обратно, а `размер` и
`смещение` между собой несовместимы без явного `как` — знак не
переносится неявно. Диагностика печатает написанное имя: `требуется
размер, получено смещение`; составные формы (`цел.верх`, `нат.шаг`)
печатаются как записаны.

### Примеры

```raz
код_ошибки цел.рост = -1
размер_файла нат.верх = 4096
символ сим = 65
готово лог = да
точность вещ.верх = 3.1415926535
длина_строки размер = строка.длина
позиция смещение = стр_найди(строка, "42")
```

### Замечания для реализации

1. Типы вида `цел.верх` используют точку. В синтаксической позиции типа
   точка читается как часть составного имени типа; в позиции выражения —
   как доступ к полю, модулю или методу. Различение делает парсер по
   контексту позиции.

2. `вещ.*`, `век` и уровень `пик` (128 бит) — целевые имена канона.
   Реализованы `вещ.верх` (IEEE-754 binary64) и `вещ.рост` (binary32):
   литералы, арифметика `+ − × ÷`, сравнения с семантикой NaN,
   явные приведения `как` цел↔вещ и вещ↔вещ, составные присваивания,
   параметры и результат через xmm-регистры. Реализован `век` —
   128-битный SIMD-вектор (см. ниже). Остальные уровни
   (`вещ.старт/шаг/шагм/пик`) и `пик` компилятор пока
   отклоняет — реализация идёт отдельными вехами.

   В семействе `вещ` половинная точность зафиксирована сразу:
   `вещ.шаг` — IEEE-половинная (f16), `вещ.шагм` — «мозговой» формат
   bf16 (та же ширина 16 бит, иная разрядная сетка — поэтому формат
   виден в имени, а не скрыт за уровнем). Оба типа нужны для
   нейросетевых нагрузок, где 32/64 бита избыточны; `вещ.пик` —
   128-битная четверная точность.

3. Имя `стр` — и тип строки, и пространство имён строковых функций.
   Разрешение контекстное: в позиции типа `стр` — тип; в позиции
   выражения `стр.найди` — модуль. То же для `список` и имён записей:
   переменная всегда побеждает модульное имя.

4. Голые `цел`, `нат`, `вещ` без уровня — не типы. Компилятор сообщает
   «тип требует уровень: цел.верх / нат.рост / …».

### Векторные типы `век`

`век <элемент> х N` — вектор фиксированной ширины, тип первого класса:

```raz
столбец век вещ.рост х 4
ряд век нат.шаг х 16
```

- Компилятор раскладывает `век` в SIMD-регистры машины (SSE/AVX на
  x86-64, NEON на а64). Ширина, недоступная цели, — ошибка компиляции,
  а не тихий разворот в скалярный цикл. На текущем базисе x86-64
  реализован один xmm-регистр: `|элемент| × N` обязано быть 16 байтам
  (`век вещ.рост х 4`, `век вещ.верх х 2`, `век цел.шаг х 8`,
  `век нат.старт х 16` и т. д.) — иная ширина отклоняется.
- Операторы над векторами применяются поэлементно: `+ − × ÷` для
  вещественных лейнов, `+ −` и битовые `& | ^` для всех целых лейнов,
  `×` — только для 16-битных целых (pmulld/pmulq в базисе SSE2 нет —
  честная ошибка, а не разворот), целочисленного деления нет.
  Сравнения дают вектор-маску натуральных лейнов той же ширины.
- Вектор — значение первого класса: литерал `век Т х N{...}` (ровно
  N лейнов), индексация `в[и]` читает лейн, параметры и результат
  идут через xmm-регистры ABI, `отложи` сохраняет вектор.
- `повтор(скаляр)` — встроенная форма распыления: числовой скаляр
  во все лейны; тип результата — `век Т х (16/|Т|)` по типу
  аргумента (f32/f64 — одним `pshufd`, целые — через слот).
- `сумма(век)` — встроенная горизонтальная редукция: сумма всех
  лейнов в скаляр типа лейна (`век вещ.рост х 4` → `вещ.рост`).
  f32/f64 сворачиваются в xmm (`pshufd` + `addps`/`addpd` +
  скалярный добор), целые — через слот накопления.
- `повтор` и `сумма` — контекстные формы: встроенный разбор только
  при следующей `(`; как обычные идентификаторы они остаются
  свободными (`сумма % 16` — валидная переменная). Вызов с таким
  именем всегда разбирается как встроенная форма.
- Остальные редукции и шаффлы живут в `мат.век.*` (отдельная веха).
- `пик` остаётся скаляром: `век` — единственный путь к широким
  регистрам, скалярные уровни выше 128 бит не растут.
- Матрицы и тензоры — не типы языка, а записи и области поверх `век`:
  ядро РАЗУМА остаётся маленьким, библиотека несёт формы.

## 7. Семантика объявления и присваивания

Оператор `:=` удалён из канона. В переходный период он ещё читается
компилятором с предупреждением об устаревании и не может перекрывать
существующие имена; затем будет убран полностью по конвейеру §11.

### Базовое правило

```raz
имя тип = выражение
```

— это явное объявление нового имени в текущей области.

```raz
введи имя = выражение
```

— объявление с выводом типа: тип выводится из выражения компилятором.
Предпочтительная форма — явная; `введи` используется там, где тип
очевиден из правой части (`введи с = ввод()`) или его запись шумит.

```raz
имя = выражение
```

— это присваивание уже существующему имени.

### Примеры

```raz
счёт цел.верх = 0
счёт = счёт + 1

размер нат.верх = 4096
размер = размер + 1
```

### Требования к реализации

- присваивание необъявленному имени — ошибка компиляции;
- опечатка в имени — ошибка, а не создание новой переменной;
- повторное объявление имени в области — ошибка;
- `введи` не может перекрывать видимое имя (параметр, функцию, константу);
- скрытое затенение не допускается без отдельного явного механизма;
- вывод типа — только через `введи`, не через голое `=`.

### Переменные циклов

Счётчики циклов называются смысловыми русскими именами по контексту:
`инд` (индекс), `поз` (позиция), `ном` (номер), `сим`, `байт`, `стрк`.
Однобуквенные `i`/`j`/`k` не употребляются; вложенные циклы получают
свои смысловые имена либо `инд`, `инд2`, `инд3`.

### Имена должны быть понятны

Имя переменной, поля, параметра и функции читается как слово или
осмысленное сокращение русского слова. Правила:

- никаких латинских имён внутренних сущностей: не `seen`, а `взято`;
  не `decls`, а `объявы`; не `stmts`, а `операторы`;
- однобуквенные имена (`n`, `v`, `s`, `e`, `о`, `т`, `р`) запрещены —
  читатель не должен угадывать смысл по типу;
- сокращения допустимы только для слов, которые встречаются часто
  и сокращаются всеми одинаково: `стр`, `функ`, `колво`, `смещ`,
  `разм`, `адр`, `искр`, `кон`, `соб`;
- если сокращение неочевидно — пишется полное слово: `суффикс`,
  `объявления`, `операторы`, `регистров`;
- приёмник метода называется по сути объекта: `отл *Отлад`,
  `ген *Ген`, `парс *Парсер` — а не одной буквой;
- имена из официальных спецификаций железа и форматов могут
  сохранять спецификационные обозначения в комментарии рядом
  (биты `REX.W/R/X/B`, поля `DEBUG_EVENT`, регистры `DR6`);
- внешние ABI-имена (`CreateProcessW`, `kernel32`) — по старому
  правилу, остаются английскими.

## 8. Модули и пространства имён

### Импорт

```raz
взять сист.файл
взять стр
```

- Точка в имени импорта — путь модуля: `сист.файл` → `биб/сист/файл.раз`.
- Поиск идёт по тем же базам, что и для плоских имён (каталог исходника,
  `биб/`, `../биб/`; `lib/` — устаревший запасной путь перехода),
  с учётом целевого суффикса `.windows`/`.linux`.
- Импорт без псевдонима открывает последнее имя пути:
  `взять сист.файл` открывает `файл`.
- Полный путь тоже работает: `сист.файл.прочти(...)`.
- Позже допустим псевдоним: `взять сист.файл как ф`.

### Обращение в выражениях

```raz
текст стр = файл.прочти("вход.txt")
позиция цел.верх = стр.найди(текст, "42")
общий нат.верх = мат.цел.нод(а, б)
```

Правила разрешения `a.b.c` в позиции выражения:

1. Если `a` — локальная переменная или параметр, это доступ к полю/методу.
2. Иначе ищется самый длинный зарегистрированный модульный префикс
   (`мат.цел`, `сист.файл`, `файл`); остаток склеивается в имя
   `префикс_остаток` (`мат.цел.нод` → `цел_нод`, `файл.прочти` → `файл_прочти`).
3. Затем — прямое склеивание всей цепочки (`a_b_c`).
4. Затем, для двухчленной цепочки по открытому модулю — голое имя
   (`конс.печать` → `печать`, переходная мера для библиотек без префикса).
5. Ничего не найдено — обычная ошибка «нет поля / неизвестное имя».

Тем же правилом резолвятся модульные константы (`мат.вещ.ПИ` → `вещ_ПИ`)
и функции как значения.

### Видимость `открыто`/`скрыто`

```raz
открыто функ файл_прочти(путь стр) стр: ...
скрыто конст _МАГИЯ = 0x51C0DE51
функ внутренняя() ...            ; без префикса — скрытая
```

- `открыто` — имя доступно другим модулям; это и есть лицо модуля (ипп).
- `скрыто` — имя доступно только внутри своего модуля.
- Отсутствие префикса равнозначно `скрыто`: безопасное умолчание,
  случайная протечка внутренних имён невозможна.
- Проверка выполняется при разрешении глобальных имён во время
  компиляции. Нарушение — ошибка «имя «X» скрыто в модуле «файл»».
- Скрытое объявление свободно используется внутри своего модуля —
  инкапсуляция не мешает реализации.
- Стандартная библиотека размечается `открыто` только по согласованной
  политике ипп; внутренние помощники остаются скрытыми.

### Интерфейсный кэш `.рми`

- Кэш `<имя>.<цель>.рми` лежит рядом с исходником и хранит интерфейс
  модуля вместе с готовым фрагментом кода и данных ИСКРЫ.
- Кэш не ослабляет видимость: скрытые символы сериализуются с флагом
  `0` и остаются недоступными другим модулям.
- Ключ актуальности — версия формата, цель, `--режим`, `--память`,
  `-O0/-O1`, хеш исходника и хеши зависимостей; несовпадение — молчаливая
  перестройка из исходника. Повреждённый или чужой кэш не является
  ошибкой.
- Корневой модуль программы не кэшируется: кэш описывает интерфейс,
  а не программу.
- Сборка из кэша обязана давать побайтно тот же выход, что и сборка
  из исходников: кэш — ускорение, не новая семантика.
- `.рми` — производный артефакт и не хранится в репозитории.

## 10. Канон ИСКРЫ

### Общие правила

- ИСКРА остаётся короткой и строгой.
- Мнемоники, директивы и регистры — ВЕРХНИМ РЕГИСТРОМ.
- Метки и имена функций — в нижнем регистре.
- Используются только русские служебные имена.

### Префиксы

| Категория | Канон |
|---|---|
| Функция | `ф_` |
| Метка | `м_` |
| Стандартная библиотека | `стд_` |
| Служебное | `служ_` |
| Системное | `сист_` |
| Данные строки | `стрд_` |
| Строковый объект | `стр_` |
| Константа | `КОНСТ_` |

### Метки генератора

Старый стиль вида `м2_пока`, `м63_есликон` неканоничен.

Канон (контекст функции + роль + номер):

```text
м_главная_цикл_начало_1
м_главная_цикл_конец_1
м_разбор_если_конец_2
м_стр_число_выход
```

### Псевдоинструкции

```asm
ВХОДКАДРА 16
ВЫХОДКАДРА
```

Развёртывание:

```asm
ВХОДКАДРА 16   →   ВСТЕК УКК / ПЕР УКК, УКС / ВЫЧ УКС, 16
ВЫХОДКАДРА     →   ПОКИНЬ
```

### Исключение

Слово `РАВНО` допускается в двух ролях:

- после имени — директива определения константы (`РАЗМЕР_БУФЕРА РАВНО 4096`);
- в позиции инструкции — условный переход при равенстве (`РАВНО м_выход`).

Это единственное осознанное контекстное исключение из правила
«один смысл — одно написание».

## 11. Версии и устаревание

ВЕЛЕС развивается без накопления слоёв: устаревшее выносится из
компилятора в инструмент миграции и исчезает, а не остаётся навсегда.

### Правило версии файла

- Первая строка исходника может нести `;версия N` (рядом с `;цель`).
- Компилятор читает файл под семантикой его версии; без отметки —
  под последней. Актуальная версия — `ВЕРСИЯ_КАНОНА = 1`; нумерация с 1.
- В ИСКРЕ прагма — `;`+слово без пробела в ведущем блоке `;`-строк;
  `;версия` действует и там (`ИСКРА_ВЕРСИЯ = 1`), РАЗУМ эмитирует её
  в каждый `.иск`. Несколько прагм на строке и неизвестные имена
  допускаются — совместимость вперёд.
- Компилятор поддерживает последние **K = 3** версии канона.
  Файл более старой версии не компилируется напрямую — его переписывает
  инструмент `переведи` на актуальный канон. Номер новее канона,
  ноль и `;версия` без номера — ошибки разбора.

### Конвейер устаревания

1. Конструкция объявлена устаревшей: компилятор предупреждает в stderr
   (один раз на конструкцию в файле, с путём и строкой), редактор
   подсвечивает `invalid.deprecated`.
2. Через две версии — ошибка компиляции («удалено, запустите переведи»).
3. Через три — конструкция вычеркнута из грамматики и кодогенератора.

Первые жители конвейера: `:=`, плоские типы `цел8`…`цел64`,
`без8`…`без64`, `бул`, `д32`, `д64`. Реализовано: `:=`, `бул` и плоские
`целN`/`безN` предупреждают с версии 1; `д32`/`д64` уже вычеркнуты из
грамматики ИСКРЫ (канон — `БАЙТ`/`СЛОВО`/`ДВСЛОВО`/`КВАД`).

### Мигратор `переведи`

`переведи` — обычная программа на РАЗУМЕ (`переведи/переведи.раз`),
собранная ВЕЛЕСОМ. Она переписывает исходники на месте:

```text
переведи файл.раз [файл2.раз ...]
```

- Правила миграции — машиночитаемая таблица (`запись Правило` +
  список `правила()`), а не проза в чейнджлоге. Набор версии 1:
  `бул` → `лог`; `цел8`…`цел128` → `цел.старт`…`цел.пик`;
  `без8`…`без128` → `нат.старт`…`нат.пик`; `имя := выражение` →
  `введи имя = выражение`.
- Заменяются только идентификаторы и операторы кода: строковые
  литералы, комментарии (`#`, `;`, включая прагмы `;версия`) и тела
  блоков `искра:` копируются побайтно. Разделители строк `\n`/`\r\n`
  и конец файла сохраняются.
- Переписывание идемпотентно: повторный запуск сообщает
  «без изменений» и не трогает файл. Несуществующий файл — ошибка
  в stderr и ненулевой код; код выхода — число необработанных файлов.
- Проверка: `тесты/переведи/` — прогон копирует вход, сравнивает
  результат с эталоном побайтно, проверяет идемпотентность и
  компилирует мигрированный файл.

### Правила

- На каждую задачу — один канонический способ. Лучший способ появился —
  старый идёт в конвейер, а не остаётся «для совместимости».
- Миграции описываются машиночитаемо (правила для `переведи`), а не
  прозой в чейнджлоге.
- Совместимость доказывается тестами: `тесты/канон/версия_N/` держит
  программы каждой поддерживаемой версии.
- `переведи` — обычная программа на РАЗУМЕ, собранная ВЕЛЕСОМ.

### Стабильность модулей биб

- В шапке модуля — отметка `;стабильно` или `;развивается`
  (первая строка, как прагма; если первой стоит `;версия` — следом).
- `;развивается` может менять ипп свободно до заявленной версии.
- Ломающее изменение `;стабильно`-модуля = новый модуль с новым именем,
  а не флаги и ветки внутри старого.
- Реализовано: все модули `биб/` размечены — `стабильно`: `память`,
  `стр`, `список`, `буфер`, `основа`, `консоль.*`, `система.*`,
  `сист.файл.*`, `мат`, `мат.цел`, `мат.нат`; `развивается`:
  `узлы`, `процесс.*`, `файл.*` (переходный шим). CI проверяет,
  что у каждого `биб/**/*.раз` отметка есть в шапке.
- Совместимость версий как тест: `тесты/канон/версия_N/` держит
  представительную программу каждой поддерживаемой версии;
  `версия_1/программа.раз` закреплена `;версия 1` и идёт в прогоне.

## 12. Модель целей

Цель — это пара **система-машина**, а не одно слово:

```text
windows-x86_64
linux-x86_64
macos-x86_64
uefi-x86_64
голо-x86_64      # голое железо, без ОС
```

- Часть «система» выбирает суффикс модулей `биб/` (`.windows`,
  `.linux`, `.macos`, `.uefi`, `.голо`) и формат вывода
  (PE64 / ELF64 / Mach-O / плоский бинарь).
- Часть «машина» выбирает кодер ИСКРЫ. Архитектурно-зависимы только
  `иск/кодер.раз` и `иск/рег.раз`; лексер, парсер, таблицы символов,
  выражения и эмиттеры форматов — общие. Целевая структура:
  `иск/кодер/х86_64.раз`, `иск/кодер/а64.раз`, `иск/кодер/рв64.раз`.

### ИСКРА — промежуточное представление РАЗУМА

Каноническое решение: текст ИСКРЫ — это IR РАЗУМА. РАЗУМ ничего не
знает о машинных байтах; перенос на новую архитектуру = новый кодер
ИСКРЫ + машинные модули `биб/`. Никакого отдельного бинарного IR и
внешних бэкендов не заводится.

### Разрядность и указатели

- `нат.верх` = нативная разрядность машины и размер указателя
  (x86-64 → 64 бита; будущие машины могут дать 32 или 128).
- `пик` = всегда 128 бит — расширение, а не «нативный максимум».
- Невозможность типа на конкретной машине — ошибка компиляции
  под эту цель, а не изменение смысла типа.

## 13. Домены памяти и приборы

Память в ВЕЛЕСЕ не едина. Указатель принадлежит **домену**, и домены
не смешиваются неявно.

### Канонические домены

| Домен | Смысл |
|---|---|
| процесс | обычная память программы (домен по умолчанию) |
| прибор | память ускорителя (GPU, NPU, TPU) |
| стойкая | энергонезависимая память (NVRAM, файловые окна) |
| дальняя | NUMA-узлы, CXL-пулы, память другого прибора |

- Неявное приведение указателя между доменами — ошибка компиляции.
  Перенос между доменами — только явными операциями модуля домена
  (`прибор.скопируй_в`, `прибор.скопируй_из`).
- Выделение памяти идёт через область: `область.выдели(размер)`.
  Интерфейс области один, реализации — по доменам: процесс-heap,
  видеопамять, стойкий пул.

### Модель «хост + приборы»

РАЗУМ — язык хоста. Код ускорителя — отдельный домен компиляции:

- либо диалект ИСКРЫ устройства (`иск/кодер/нпу_*.раз` на той же
  инфраструктуре ассемблера);
- либо программа устройства строится как данные через `биб/прибор`
  и отдаётся рантайму устройства.

В обоих случаях эмиттер — это модуль на РАЗУМЕ, как сегодняшние
`иск/эльф.раз`, `иск/пе.раз`, `иск/махо.раз`.

### Квантовые вычисления

Кубиты — не память и не регистры. Квантовая программа — это схема,
построенная как данные и отправленная на исполнение. Канон: модуль
`биб/квант` строит схему, отдельный эмиттер пишет её формат. Кубитные
сущности не вводятся в типы и операторы РАЗУМА.

## 14. Модель памяти и параллелизм

Закладывается до первого многопоточного кода — задним числом модель
памяти не прикручивается.

### Базовые правила

- Обычные чтение и запись между задачами гарантий не дают: гонка по
  данным — ошибка программы.
- Вся синхронизация — только через атомарные типы и ограды канона.
- Реализация не вправе переносить, слиять или выкидывать обращения
  к нелетучей памяти и атомам.

### Атомарный тип

```raz
счёт атом нат.верх = атом.нулевой()
атом.пиши(счёт, 1, отпуск)
значение нат.верх = атом.читай(счёт, захват)
атом.добавь(счёт, 1, полный)
```

### Порядки

| Порядок | Смысл |
|---|---|
| `слабый` | только атомарность, без упорядочения |
| `захват` | чтение видит всё, отпущенное до публикации |
| `отпуск` | запись публикует всё, сделанное до неё |
| `полный` | единый порядок для всех задач |

`полный` — порядок по умолчанию, когда порядок не указан.

### Средства ИСКРЫ

- префикс `ЗАМОК` (lock) для атомарных read-modify-write;
- `СРАВОБМЕН` (cmpxchg), `ОБМЕНДОБ` (xadd), `ОБМЕН` (xchg);
- ограды `ОГРАДАЗ`, `ОГРАДАВ`, `ОГРАДАП` (lfence/sfence/mfence);
- `ПАУЗА` для спин-ожидания.

### Задачи и исполнители

- Абстракция параллелизма — задача, а не поток ОС: `задача.исполни`
  поверх исполнителя (пула ядер).
- Исполнителей может быть несколько и разных классов — это задел под
  гетерогенные машины (P/E-ядра, SoC с разными ISA).

### Метаданные вместо рефлексии

Скомпилированная программа остаётся «слепой»: таблиц имён и типов в
исполняемом образе по умолчанию нет, рантайм-рефлексии в языке нет.
По флагу `--отладка` компилятор испускает описание типов, имён и
соответствия исходным строкам в отдельную секцию или файл — её читают
СЛЕД и языковой сервер снаружи, не замедляя саму программу.

## 15. Базовая безопасность РАЗУМА

### Строгий логический тип

`лог` имеет ровно два нормализованных значения: `нет` (`0`) и `да` (`1`).
Числа, указатели и другие типы не обладают логической истинностью.

- Условия `если`, `а если`, `пока` и их постфиксных форм принимают только
  `лог`.
- Операторы `не`, `и`, `или` принимают только `лог`.
- Неявное преобразование числа или указателя в `лог` запрещено.
- Явное `число как лог` и `указатель как лог` также запрещено.
- Каноническая проверка числа — `число != 0`, указателя —
  `указатель != пусто`.
- Присваивание не является выражением: `если число = 5` — синтаксическая
  ошибка.
- Чтение и запись значения `лог` нормализуются, чтобы значение не могло
  остаться равным `2`, `255` или любому иному числу.

Строгость `лог` не зависит от режима безопасности и уровня оптимизации.
Проверки границ, безопасные срезы, диагностическая память, типы машинного
размера и интерфейсы модулей внедряются отдельными ветками по ROADMAP.

### Режимы безопасности

Компилятор имеет независимую ось безопасности `--режим`:

- `надёжно` — канонический режим и умолчание; в него по мере очереди
  ROADMAP входят динамические проверки границ, срезов, строк и
  диагностическая память;
- `быстро` — сохраняет низкоуровневые возможности: динамические проверки
  не генерируются, статические ошибки остаются; типовая безопасность и
  строгость `лог` не ослабляются;
- `--режим` независим от `-O0/-O1`: уровень оптимизации не влияет на
  режим, режим не влияет на выбор оптимизаций;
- неизвестное или отсутствующее значение — ошибка компилятора с русской
  диагностикой и ненулевым кодом завершения;
- выбранный режим испускается прагмой `;режим надёжно` или
  `;режим быстро` в начале сгенерированной ИСКРЫ, чтобы кэш, диагностика
  и последующие инструменты различали сборки разных режимов.

Сырой указатель не содержит длину: режим `надёжно` не должен создавать
впечатление проверенной границы там, где длина недоступна.

### Проверки границ массивов `Т[N]`

- Известный индекс вне `Т[N]` — статическая ошибка в обоих режимах;
  диагностика различает чтение, запись и взятие адреса.
- В `надёжно` динамическая проверка выполняется до умножения индекса на
  размер элемента; знаковый индекс ловится на `< 0`, беззнаковый — только
  на верхней границе. Индекс и база вычисляются ровно один раз.
- Сбой границы завершает процесс кодом 101 через `стд_сбой_границы` —
  стабильный обработчик с диагностикой (см. ниже).
- В `быстро` динамическая проверка не генерируется, статическая остаётся.
- Проверяются только `Т[N]`; срезы `[]Т`, строки и сырые указатели —
  следующими этапами.

### Проверки границ срезов `[]Т`

- Индексация `срез[i]` в `надёжно` проверяет `0 <= i < длина`; сбой — код
  101. Константный отрицательный знаковый индекс — статическая ошибка в
  обоих режимах.
- Создание `об[нач..кон]` / `об[нач..=кон]`: в `надёжно` знак, порядок
  `нач <= кон` и верхняя граница проверяются до арифметики длины; сбой —
  код 102. Для `..=` требуется `кон < длина` — это же ловит переполнение
  `кон + 1`. Пустые срезы `[0..0]` и `[длина..длина]` допустимы.
- Константные нарушения (порядок, отрицательные границы, конец вне `Т[N]`)
  — статические ошибки в обоих режимах.
- Срез сырого указателя в `надёжно` — предупреждение компилятора: длина
  недоступна, границы не проверяются.
- В `быстро` динамические проверки не генерируются, статические остаются.

### Проверки границ строк `стр`

- Индексация `стр[индекс]` идёт по байтам UTF-8: индекс — смещение байта,
  элемент — `сим`. В `надёжно` проверяется `0 <= индекс < длина`; сбой —
  код 101. Индекс `длина` запрещён; пустая строка не допускает чтение.
- Константный отрицательный знаковый индекс — статическая ошибка в обоих
  режимах.
- Срез строки `стр[нач..кон]` / `стр[нач..=кон]` использует те же проверки,
  что срез массива/среза: длина читается из пары `{данные, длина}`.
- `стр_срез(строка, от, по)` — не обход синтаксиса: диапазон проверяется
  всегда, неверный завершает процесс кодом 102 независимо от режима.
- В `быстро` динамические проверки индекса не генерируются, статические
  остаются; проверка внутри `стр_срез` от режима не зависит.

### Аварийные обработчики и стабильные коды

- Стабильные коды завершения: **101** — индекс/доступ за границей
  (`стд_сбой_границы`), **102** — некорректный диапазон/срез
  (`стд_сбой_среза`), **103** — ошибка выделения памяти (`стд_сбой_памяти`).
- ABI обработчика: `СЧТ` — значение, `ДАН` — предел, `ИСТ` — вид операции
  (0 чтение, 1 запись, 2 адрес, 3 срез, 4 память), `БАЗ` — номер строки,
  `Р8` — файл (резерв, 0).
- Обработчик печатает одну строку диагностики в stderr без библиотеки
  `консоль` (`WriteFile`/`write(2)`) и не выделяет память в аварийном пути.
  Пример: `разум: сбой границы: индекс -3 вне длины 4, вид 1, строка 5)`.
- `выдели`/`новый` при неудаче выделения уходят в код 103 — записи по
  нулевому указателю не происходит.
- Метки обработчиков видны в карте символов СЛЕДа: точка ставится по имени
  `стд_сбой_границы`.

### Доказуемое удаление динамических проверок

- В `надёжно` динамическая проверка опускается только при доказанном
  индексе: константа в границах, `инд & (N-1)`/`инд % K` с беззнаковым
  индексом, переменная `для и в мин..предел` с константными границами в
  пределах массива, переменная `для и в кол` для той же коллекции.
- Доказательство снимается при присваивании, затенении или взятии адреса
  переменной цикла либо коллекции внутри тела — сомнительная проверка
  всегда сохраняется.
- Доказательство действует на уровне генерации и не зависит от `-O0/-O1`;
  оптимизатор не является частью доказательства.

### Диагностическая память `--память обычно|проверка`

- Независимая от `-O0/-O1` и `--режим` ось. По умолчанию `обычно`:
  `выдели`/`новый`/`освободи` работают напрямую с кучей, диагностической
  инфраструктуры в ИСКРЕ нет.
- В `проверка` каждый блок получает заголовок 48 байт (размер, магия
  `0x51C0DE51`, строка выделения, связь списка, состояние) и огранку
  16 байт `0x5A` после пользовательской области; узлы связаны списком от
  `стд_пам_голова`.
- `освободи` обходит список и проверяет членство: чужой указатель — вид 0,
  повторное освобождение — вид 1, порча огранки — вид 2, порча магии
  заголовка — вид 3. Область заливается `0xDD`, узел остаётся в карантине
  (ОС его не получает) — повторное освобождение обнаруживается.
- Стабильный код **104** (`стд_сбой_целост`): диагностика в stderr —
  `разум: сбой целостности памяти: адрес N, вид V, строка L)`.
- Перед выходом `стд_пам_фин` проверяет живые узлы (магия и огранка) и
  считает утечки: `разум: утечки памяти: N блоков, M байт` → код 104.
- Ограничения: запись в уже освобождённый блок не перехватывается (область
  отравлена `0xDD`, но доступ не ловится); прямой `система.выход` обходит
  финальную проверку; сырой указатель по-прежнему не содержит длину —
  проверка идёт по членству в списке, а не по границам доступа.
- Аварийный путь не выделяет память; обработчики видны в карте символов
  СЛЕДа.

## 16. Статус внедрения

Оперативная очередь и критерии PR находятся в [../ЗАДАЧИ.md](../ЗАДАЧИ.md),
памятка новой сессии — в [../AGENTS.md](../AGENTS.md). Следующий этап после
диагностики памяти — `фича/типы-размер-смещение`; остальные проверки
выполняются последующими отдельными PR.

Реализовано:

- строгое `=` и явное объявление `имя тип = выражение`;
- `введи имя = выражение` — объявление с выводом типа;
- `:=` — переходная форма с предупреждением, без перекрытия имён;
- метки генератора `м_<функция>_<контекст>_<номер>`;
- псевдоинструкции `ВХОДКАДРА` / `ВЫХОДКАДРА`;
- точечные типы `цел.*`, `нат.*`, `лог` (старые формы — синонимы);
- строгий `лог`: условия и логические операторы только для `лог`,
  значения нормализованы до `нет`/`да`, числовые приведения запрещены;
- ось безопасности `--режим надёжно|быстро`: `надёжно` по умолчанию,
  режим независим от `-O0/-O1` и фиксируется прагмой `;режим` в ИСКРЕ;
- границы массивов `Т[N]`: статическая ошибка в обоих режимах,
  динамическая проверка в `надёжно`, сбой кодом 101;
- границы срезов `[]Т`: индекс и диапазон создания, коды 101/102;
- границы строк `стр`: байтовая индексация по длине UTF-8, `стр_срез`
  проверяет диапазон всегда, коды 101/102;
- доказуемое удаление динамических проверок: доказанные индексы
  (`инд & (N-1)`, `инд % K`, переменные `для` в пределах коллекции) не
  получают проверку, недоказанные — сохраняют код 101;
- аварийные обработчики `стд_сбой_границы`/`стд_сбой_среза`/
  `стд_сбой_памяти` со стабильными кодами 101/102/103 и минимальной
  диагностикой в stderr без `консоль`;
- точечные пути в `взять` и квалифицированные обращения `модуль.имя`;
- машинные слова `размер`/`смещение` и миграция библиотеки и ядра;
- диагностическая память `--память обычно|проверка` (сбои кодом 104);
- видимость модулей `открыто`/`скрыто` с безопасным умолчанием;
- интерфейсный кэш `.рми` — компиляция модулей без перечтения исходников.

Отдельными ветками:

- `вещ.*` (`вещ.шаг`, `вещ.шагм`, `вещ.рост`, `вещ.верх`, `вещ.пик`),
  `век` и `пик` — с появлением кодогенерации плавающей точки и SIMD;
- `--отладка` — испуск метаданных типов/имён для СЛЕДа и LSP;
- полная перестройка `биб/` под канонические пути и имена;
- псевдонимы импорта `взять … как …`;
- методный стиль поверх модульного (`текст.найди("ошибка")`);
- снятие переходных синонимов (`:=`, `цел64`, `бул`, …).

Разделы 11–15 (версии и устаревание, модель целей, домены памяти,
модель параллелизма, базовая безопасность) — зафиксированный канон;
внедрение идёт вехами по ROADMAP.md: `;версия` и `переведи`, пары
система-машина, домены указателей, `атом`/`ЗАМОК`, ограды и проверки
границ.

## 17. Короткая формула канона

- Сокращается путь, не сокращается действие.
- По умолчанию — единственное число.
- Типы описываются через семейство и уровень.
- Объявление всегда явное; `=` только пишет в существующее имя.
- РАЗУМ остаётся строгим, но без визуального мусора.
- ИСКРА остаётся короткой и железной.
- Всё внутреннее именование — только на русском.
- Устаревшее уходит по конвейеру и не накапливается слоями.
- Цель — пара система-машина; ИСКРА — единый IR РАЗУМА.
- Память делится на домены; приборы — не хост.
- Параллелизм только через атомы и ограды канона.
