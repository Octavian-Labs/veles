# РАЗУМ — спецификация системного языка (EBNF + семантика)

> Состояние спецификации сверено 2026-09-21. РАЗУМ — средний уровень экосистемы ВЕЛЕС:
> ИСКРА (ассемблер) → **РАЗУМ** (системы) → ЯР (флагман).
>
> Назначение: ядра ОС, драйверы, рантаймы, компиляторы — включая будущий
> компилятор РАЗУМА (самораскрутка) и рантайм Яра.

## 0. Принципы дизайна

- **Статическая типизация.** Объявление явное: `х цел.верх = 5`;
  присваивание `=` — только уже объявленным именам.
- **Никакого GC.** Ручная память: `новый`/`освободи`, адреса и размеры явные.
- **Ноль скрытых действий.** Нет неявных аллокаций, копирований, исключений.
- **Компиляция в ИСКРУ.** Компилятор генерирует текст `.иск`, ассемблер
  производит PE64, ELF64 или Mach-O x86-64.
- **Читается по-русски** там, где это не вредит точности: `если`,
  `а если`, `пока`, `х в 0..10`, `х как нат.рост`.

## 1. Типы

```ebnf
тип   := простой | "*" тип | тип "[" [ число ] "]" | "функ" "(" [ типы ] ")" [ тип ]

простой :=
    "цел.старт"  "цел.шаг"  "цел.рост"  "цел.верх"  "цел.пик"
  | "нат.старт"  "нат.шаг"  "нат.рост"  "нат.верх"  "нат.пик"
  | "лог"                                ; да / нет
  | "сим"                                ; = нат.старт
  | "вещ.старт" "вещ.шаг" "вещ.рост" "вещ.верх" "вещ.пик"
                                       ; IEEE-754 (этап 2, нужен SSE)
  | "цел.пик"  "нат.пик"                 ; 128-битные (этап 2)
  | "цел8".."цел64" "без8".."без64" "бул" ; старые имена — алиасы перехода
  | "пусто"                              ; void: нет значения
  | "стр"                                ; { данные *нат.старт, длина нат.верх }
  | имя                                  ; записи, перечисления, синонимы
```

| Конструкция | Смысл |
|-------------|-------|
| `*Т` | указатель на Т (`*пусто` ≈ void*) |
| `Т[N]` | массив фиксированной длины |
| `[]Т` | срез: `{ данные *Т, длина нат.верх }` |
| `функ(цел.верх) цел.рост` | тип функции (для указателей на функции) |

### Строгий `лог`

`лог` — отдельный тип, а не целое с соглашением «ноль/не ноль».
Единственные его значения — `нет` (`0`) и `да` (`1`). Компилятор
нормализует чтение и запись логических значений, поэтому и повреждённый
сырой байт при чтении как `лог` становится `нет` или `да`.

Условия `если`, `а если`, `пока` и их постфиксных форм обязаны иметь тип
`лог`. Операторы `не`, `и`, `или` также принимают только `лог`:

```raz
готово лог = да
если готово и число != 0:
    ...
если указатель != пусто:
    ...
```

Числа и указатели не преобразуются в `лог` неявно. Запрещены `если 1`,
`если указатель`, `готово лог = 2`, `да и 1` и `число как лог`.
Каноническая запись — явное сравнение: `число != 0`,
`указатель != пусто`. Присваивание не является выражением, поэтому
`если число = 5` остаётся синтаксической ошибкой.

## 2. Переменные и константы

```ebnf
объявление := имя тип "=" выражение                    ; каноническая форма
            | "введи" имя "=" выражение                ; вывод типа
            | имя ":=" выражение                       ; устарело: предупреждение
            | "конст" имя "=" выражение                ; время компиляции
            | "тип" имя "=" тип                        ; синоним типа

присваивание := цель "=" выражение                     ; только объявленным именам
```

```go
счёт цел.верх = 0              ; объявление: имя тип = выражение
счёт = счёт + 1                ; присваивание существующему имени
буфер: нат.старт[256]          ; аналогично: буфер нат.старт[256]
размер нат.верх = 4096
конст ШИРИНА = 10
тип хендл = нат.верх            ; свой HWND
```

## 3. Функции

```ebnf
функция := "функ" имя "(" [ параметры ] ")" [ тип ] блок
         | "функ" "(" приёмник ")" имя "(" [ параметры ] ")" [ тип ] блок  ; метод
параметры := имя { "," имя } тип { "," имя { "," имя } тип }
приёмник  := имя тип
```

Типы идут **после** имён, группы с одним типом схлопываются:

```go
функ площадь(ш, в цел.верх) цел.верх:
    верни ш * в

функ главная() цел.рост:
    верни 0

запись Точка: х, у цел.верх
функ (т Точка) квадрат_нормы() цел.верх:
    верни т.х * т.х + т.у * т.у
```

## 4. Управление

```ebnf
если_оп    := "если" выр блок { "а" "если" выр блок } [ "иначе" блок ]
выбор      := "выбор" выр блок_вариантов      ; образцы: литералы и a..b
пока_оп    := "пока" выр блок
для        := "для" имя "в" выр блок          ; диапазон или массив/срез
           | "для" имя "," имя "в" выр блок   ; (индекс, элемент)
вечно      := "вечно" блок
управление := "верни" [ выр ] | "хватит" | "следующий" | "отложи" выр
```

- `отложи выр` — defer: выполнится при выходе из функции (LIFO).
- Постфиксные модификаторы (как в Яре): `действие если усл`, `действие пока усл`.

## 5. Указатели и память

```ebnf
адрес      := "&" цель                      ; взять адрес
разымен    := "*" выражение                 ; разыменовать
```

```go
новый(Т)            ; выделить sizeof(Т), вернуть *Т   (стдлиб: куча.взять)
освободи(указ)      ; вернуть память
размер(Т/выр)       ; sizeof — время компиляции
смести(указ, тип)   ; reinterpret_cast → или короче: указ как *нат.старт
```

Приведение типов — постфиксное `как`: `х как нат.рост`, `указ как *цел.верх`.
Это единственный способ смены типа — никаких неявных конверсий. Приведение
числа или указателя `как лог` запрещено: логическое значение получают явным
сравнением с `0` или `пусто`.

## 6. Внешние функции и встроенная ИСКРА

```ebnf
внеш      := "внеш" строка "функ" имя "(" [ параметры ] ")" [ тип ]
искра     := "искра" ":" НС ОТСТУП { строка_искры } СНЯТИЕ
```

```go
внеш "kernel32" функ ExitProcess(код нат.рост)

функ выход(код нат.рост):
    искра:
        ПЕР СЧТМ, код        ; локали и параметры видны по имени
        ВЫЗОВ ExitProcess
```

Блок `искра:` вставляет текст ИСКРЫ напрямую в вывод компилятора —
низкоуровневый люк для syscall, портов ввода-вывода, привилегированных
инструкций. Незаменим при написании ОС.

Имена локальных переменных и параметров внутри блока подставляются
компилятором как адреса `[УКК±смещение]` — ассемблерные строки остаются
сырым кодом, но могут читать и писать переменные РАЗУМА.

## 7. Модули

```ebnf
взять := "взять" путь { "," путь }   ; путь = имя { "." имя }
```

Без заголовочных файлов: всё объявленное с большой буквы — экспортируется.
Точка в пути импорта означает подкаталог: `взять сист.файл` ищет
`сист/файл.раз`. Модуль ищется рядом с импортирующим файлом, затем в
`биб/` рядом и уровнем выше. Каждый файл подключается один раз (ключ —
нормализованный реальный путь); циклические импорты отсекаются.

Точка в выражении — доступ к экспортированному имени модуля:
`сист.файл.прочти("данные.txt")`, `мат.цел.нод(а, б)`. Резолвер
раскрывает цепочку слева направо: `сист.файл.прочти` → `файл.прочти` →
`файл_прочти`. Различение точки-поля и точки-модуля — по контексту
(семантика, не лексер).

Платформенные реализации: `взять консоль` сначала ищет
`консоль.<цель>.раз` (`консоль.windows.раз`, `консоль.linux.раз`,
`консоль.macos.раз`), затем нейтральный `консоль.раз`.

Стандартная библиотека — `биб/`:

```go
взять основа          ; зонтик: память + стр + список + консоль + сист.файл + система
взять стр             ; только строки
взять сист.файл       ; файловый ввод-вывод (биб/сист/файл.<цель>.раз)
взять мат             ; зонтик математики: мат.цел + мат.нат

печать("текст")       ; stdout
печатьстр("строка")   ; + перевод строки
печатьцел(6 * 7)      ; Ответ: 42
введи с = ввод()      ; весь stdin до EOF
выход(код)            ; завершить процесс
стр_склей(а, б)       ; новая строка в куче
стр_равны(а, б)       ; лог
стр_срез(с, а, б)     ; подстрока без копирования; диапазон проверяется (102)
стр_найди(с, "под")   ; позиция или -1
стр_число("42")       ; разбор десятичного числа (со знаком)
стр_в_нуль(с)         ; копия ASCIIZ — для WinAPI/си-интеропа
это_цифра(б)          ; предикаты: это_буква/это_цифра/это_пробел/это_знак
цел_в_стр(ч)          ; десятичное представление
файл_прочти("путь")   ; стр или пусто при ошибке
файл_запиши("путь", с); лог
с *Список = список_новый()   ; динамический массив нат.верх (для токенов/AST)
список_добавь(с, x); список_получи(с, i); список_свободен(с)
скопируй(куда, откуда, n); заполни(указ, б, n); равна_память(а, б, n)
выдели(n)             ; n байт из кучи (встроенная, как новый)
```

## 8. Грамматика (выражения)

Приоритеты совпадают с Яром, плюс:

```ebnf
выражение  := или_выр [ "как" тип ]*          ; приведение — самый слабый постфикс
атом       := число | строка | "да" | "нет" | "пусто"
            | имя | "(" выр ")" | литерал | "новый" "(" тип ")"
            | "размер" "(" тип ")"
литерал    := тип "{" [ элем {"," элем} ] "}"     ; записи и массивы
элем       := [ имя ":" ] выражение
срез_оп    := выр "[" выр (".." | "..=") выр "]"  ; об[a..b] -> []Т
```

```go
т Точка = Точка{х: 3, у: 4}          ; именованные поля
т2 = Точка{3, 4}                     ; позиционные — по порядку полей
числа нат.старт[5] = нат.старт[5]{10, 20, 30, 40, 50}
введи ср = числа[1..4]               ; []нат.старт: {данные: числа+1, длина: 3}
ф функ(цел.верх) цел.верх = удвоить        ; указатель на функцию
н = ф(21)                            ; косвенный вызов
```

## 9. Пример — «Привет, мир!» на РАЗУМЕ (Windows)

```go
внеш "kernel32" функ GetStdHandle(деск нат.рост) нат.верх
внеш "kernel32" функ WriteFile(хендл нат.верх, буф *нат.старт,
                               колво нат.рост, записано *нат.рост, овер *пусто) цел.рост
внеш "kernel32" функ ExitProcess(код нат.рост)

функ главная():
    сооб стр = "Привет, мир!\r\n"        ; стр: {данные, длина}
    записано нат.рост = 0
    введи х = GetStdHandle(0xFFFFFFF5)
    WriteFile(х, сооб.данные, сооб.длина как нат.рост, &записано, пусто)
    ExitProcess(0)
```

И то же через `искра:` без единого внешнего вызова — уже сегодня.

## 10. Стратегия реализации

```text
исходник .раз → лексер → AST → проверка типов → генератор → оптимизатор
                                      │
                                      ▼
                              текст ИСКРЫ (.иск)
                                      │
                                      ▼
                            PE64 / ELF64 / Mach-O
```

- Генератор сочетает стековые промежуточные значения с регистровыми локалями;
  `-O0` отключает пипхол, `-O1` включает его.
- Ось безопасности независима от оптимизации: `--режим надёжно` (умолчание)
  и `--режим быстро`; выбранный режим хранится в генераторе и испускается
  прагмой `;режим надёжно|быстро` в начале ИСКРЫ. Неизвестное значение —
  ошибка компилятора с ненулевым кодом.
- ABI: Windows x64 — rcx/rdx/r8/r9 и теневое пространство; Linux/macOS —
  SysV x86-64 с платформенными системными вызовами.
- Компилятор написан на РАЗУМЕ и компилирует сам себя через ИСКРУ.
  Побайтный фикс-поинт проверяется в CI на Windows, Linux и macOS.
- Python не является частью современной цепочки сборки.

## 11. Реализовано (v0.2)

- Методы `функ (т Точка) имя(...)` и `функ (т *Точка) имя(...)`; вызов
  `об.имя(...)`. Приёмник передаётся первым аргументом как `*запись`
  (приёмник по значению пока получает указатель — семантика копии — этап 3).
- Косвенные вызовы: переменные и параметры типа `функ(...)`, вызов через
  `ВЫЗОВ Р11` (ИСКРА умеет `ВЫЗОВ регистр`/`ВЫЗОВ [память]`).
- Литералы `Тип{...}` для записей (именованные и позиционные поля) и
  массивов; незаполненные поля обнуляются. Проверка типов элементов и
  диапазона числовых литералов.
- Срез `об[a..b]` / `об[a..=b]` — для массивов, указателей, срезов и `стр`;
  результат — пара `{данные, длина}`.
- `взять модуль` — загрузка `.раз`-файлов (рядом с источником и в `биб/`),
  защита от циклов. Фундамент стдлиб «основа».
- `искра:` видит локали и параметры по имени (подстановка `[УКК±off]`).

### v0.3 — стдлиб «основа»

- `биб/`: `основа` (зонтик), `память` (заполни/скопируй/равна_память на чистом
  РАЗУМЕ), `стр`, платформенные `консоль`/`система`/`файл`, `список`.
- Платформенные модули `имя.<цель>.раз` с приоритетом над нейтральным.
- Встроенная `выдели(n)` — n байт кучи во время исполнения.
- Строки представлены парой `{данные *нат.старт, длина нат.верх}`; стдлиб собирает их
  через служебную запись `_стрпара` + `как стр`.

### v0.4 — стдлиб: файлы, ввод, система, список

- `система.{windows,linux,macos}`: `выход(код)` — ExitProcess / sys_exit /
  BSD exit (0x2000001).
- `файл.{windows,linux,macos}`: `файл_прочти` (стр или пусто), `файл_запиши` (лог).
  Windows — CreateFileA/ReadFile/WriteFile/CloseHandle; Linux — syscalls
  open/lseek/read/write/close через `искра:`; macOS — те же BSD-вызовы
  с базой 0x2000000, ошибка возвращается через carry.
- `консоль.*`: `ввод()` — весь stdin до EOF (буфер 1 МиБ) — входной канал
  для будущего компилятора на РАЗУМЕ.
- `стр`: `стр_в_нуль` (ASCIIZ), `стр_найди`, `стр_число`, предикаты
  `это_цифра`/`это_буква`/`это_пробел`/`это_знак`.
- `список.раз`: динамический массив `Список` (нат.верх-элементы, рост ×2) —
  основа для токенов и AST при самораскрутке.
- Компилятор: параметры функции видны при выводе типов через `введи` в теле;
  указатели проверяются по базовому типу (`*Точка ≠ *Другое`,
  `*пусто` — универсальный); метки `и`/`или` без пробелов.

### v0.5 — цель macos (x86-64)

- `разум --цель macos` генерирует ИСКРУ с прагмой `;цель macos`;
  `иск/махо.раз` эмитит статический Mach-O `MH_EXECUTE` x86_64:
  `LC_SEGMENT_64 __TEXT` (RX) + `__DATA` (RW) + `LC_MAIN`, без dyld.
- Платформенные модули `биб/*.macos.раз`: `система` (exit 0x2000001,
  `аргументы` через сохранённый указатель стека — ядро кладёт
  argc/argv на исходный RSP), `консоль` (write/read 0x2000004/0x2000003),
  `сист/файл` (open/read/write/close/unlink), `процесс`
  (fork/execve/wait4/dup2). Ошибки BSD-сисвызовов возвращаются через
  carry и нормализуются в -1.
- `хост_не_вин()` заменил `хост_линукс()` — общий предикат
  «не-Windows» для linux+macos ветвлений.

### v0.6 — канон объявлений и строгий `лог`

- Канонические объявления: `имя тип = выражение` и
  `введи имя = выражение`; `:=` — устаревшая переходная форма.
- Внутренние имена приведены к понятным русским формам.
- Условия и операторы `не`/`и`/`или` принимают только `лог`.
- `лог` нормализуется до `нет`/`да`; числовое и указательное `как лог`
  запрещено.
- Нативная матрица строгого `лог` входит в прогон 24/24 и CI трёх ОС.

### v0.7 — ось безопасности `--режим`

- CLI принимает `--режим надёжно` и `--режим быстро`; без флага выбирается
  `надёжно`. Неизвестное или отсутствующее значение завершает компиляцию
  русской ошибкой и ненулевым кодом.
- Режим передаётся в `ген_новый` третьим параметром и хранится в записи
  `Ген`; сгенерированная ИСКРА начинается прагмой `;режим надёжно` или
  `;режим быстро`, чтобы последующие этапы различали диагностику и кэш
  режимов.
- `-O0/-O1` — отдельная ось: уровень оптимизации не меняет режим
  безопасности, а режим не меняет строгость `лог`.
- Сами проверки границ в этот этап не входят: `надёжно` пока равен
  `быстро` по наблюдаемой семантике, кроме отметки режима в выводе.

### v0.8 — границы массивов `Т[N]`

- Известный (сворачиваемый) индекс вне `Т[N]` — статическая ошибка
  компиляции в обоих режимах; диагностика различает чтение, запись и
  взятие адреса.
- В `надёжно` динамическая проверка испускается до умножения индекса на
  размер элемента: знаковый индекс ловится на `< 0`, беззнаковый — только
  на верхней границе. Сбой вызывает `стд_сбой_границы` — аварийный выход
  с кодом 101 (вид операции передаётся в регистре для будущей диагностики).
- В `быстро` динамическая проверка не генерируется, статическая остаётся.
- Индекс и база массива вычисляются ровно один раз.
- Проверяются только массивы `Т[N]`; срезы, строки и сырые указатели —
  следующими этапами (указатель не несёт длину).

### v0.9 — границы срезов `[]Т`

- Индексация `срез[i]` в `надёжно` проверяет `0 <= i < длина` (длина читается
  из пары `{данные, длина}`); сбой — код 101. Константный отрицательный
  знаковый индекс — статическая ошибка в обоих режимах.
- Создание `об[нач..кон]` и `об[нач..=кон]`: начало и конец вычисляются по
  одному разу; в `надёжно` проверяются знак, порядок `нач <= кон` и верхняя
  граница до вычисления длины среза — сбой код 102. Для `..=` верхняя
  граница `кон < длина` (переполнение `кон + 1` покрыто этой проверкой).
- Источники: массив `Т[N]` (граница `N` статическая), срез и строка
  (длина из `{данные, длина}`), строка даёт `[]сим`. Пустые срезы
  `[0..0]` и `[длина..длина]` допустимы.
- Срез сырого указателя в `надёжно` — предупреждение компилятора
  (длина недоступна, границы не проверяются); проверки не генерируются.
- В `быстро` динамические проверки не генерируются, статические остаются.

### v0.10 — границы строк `стр`

- Индексация `стр[индекс]` идёт по байтам UTF-8: индекс — смещение байта,
  элемент — `сим`. В `надёжно` проверяется `0 <= индекс < длина` (длина из
  пары `{данные, длина}`); сбой — код 101. Индекс `длина` запрещён, пустая
  строка не допускает чтение. Константный отрицательный знаковый индекс —
  статическая ошибка в обоих режимах.
- Срез строки `стр[нач..кон]` и `стр[нач..=кон]` использует те же проверки,
  что срез массива/среза (v0.9): длина берётся из пары, сбой — код 102.
- `стр_срез(строка, от, по)` проверяет `от <= по <= длина` всегда — это
  библиотечная функция, а не обход синтаксиса: неверный диапазон завершает
  процесс кодом 102 независимо от режима.
- В `быстро` динамические проверки индекса не генерируются, статические
  остаются; проверка внутри `стр_срез` от режима не зависит.

### v0.11 — аварийные обработчики и стабильные коды

- Три стандартных обработчика вместо одного общего: `стд_сбой_границы`
  (код **101**), `стд_сбой_среза` (**102**), `стд_сбой_памяти` (**103**).
  Испускаются по битам `нужны_стд`: 4/8/16; бит 16 ставится вместе с битом 1
  — `стд_выдели` при неудаче `HeapAlloc`/`mmap` уходит в 103, записи по
  нулевому указателю не происходит.
- ABI обработчика: `СЧТ` — значение (индекс/граница/размер), `ДАН` — предел,
  `ИСТ` — вид операции (0 чтение, 1 запись, 2 адрес, 3 срез, 4 память),
  `БАЗ` — номер строки исходника, `Р8` — файл (резерв, 0).
- Минимальная диагностика в stderr без библиотеки `консоль`: хелперы
  `стд_печ_стр`/`стд_печ_чис` пишут через `WriteFile`(GetStdHandle(-12)) на
  Windows и `write(2)` на SysV. Пример: `разум: сбой границы: индекс -3 вне
  длины 4, вид 1, строка 5)`. Числа печатаются знаково.
- Все обработчики имеют пролог `ВСТЕК УКК / ПЕР УКК, УКС`, а завершающий
  невозвратный вызов закрывается `НОП` — метки видны в карте символов СЛЕДа,
  точка ставится по имени `стд_сбой_границы`.
- Аварийный путь не выделяет память: фрагменты текста лежат в секции данных,
  буфер числа — в кадре обработчика.
- `стр_срез` по-прежнему завершает кодом 102 через `система.выход` — это
  библиотечный уровень, диагностики там нет; код стабилен.
- В `быстро` обработчики не испускаются вместе с проверками.
