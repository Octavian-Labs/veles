# Пайплайн ВЕЛЕС — дизайн уровней и швов

Документ фиксирует архитектуру компиляторной цепочки: какие представления
существуют, какие контракты на каждом шве и что закладывается заранее под
ЯР, JIT, отладчик и оптимизаторы. Этапы реализации — ROADMAP.md и
ROAD_MAP_2.md (этап Ж); этот документ — постоянная спецификация устройства.

## Четыре уровня представления

```text
ЯР (будущее) ──┐
               │
РАЗУМ ─────────┤
               ▼
  [Уровень 4]  AST + типы        разум: лексер → парсер → узлы → типизация
               │                 внутреннее фронтенда, не контракт;
               │                 здесь живёт высокий оптимизатор
               ▼
  [Уровень 3]  поток инструкций  ШОВ №1 «фронт → бэкенд»: билдер иб
               │                 каждая эмиссия несёт позицию .раз
               ▼
  [Уровень 2]  узлы ИСКРЫ        *Узел(И_ИНСТР/И_ДИР/И_МЕТКА/И_РАВНО) + *Опер
               │                 низкий оптимизатор: пипхол, CFG, регистры
               ▼
  [Уровень 1]  *Прог → *План → *Дво   раскладка: метки, импорты, секции
               │                 План — абстракция цели: файл | память
               ▼
  [Уровень 0]  байты файла или исполняемой страницы
               пе/эльф/махо → файл;   страница RWX → JIT
```

Боковой вечный формат — **текст `.иск`**: сериализация уровня 2, а не
внутренний IR. Он нужен СЛЕДу, ручному ассемблеру, `искра:`-блокам в биб,
тестам и миграторам; версионируется прагмой `;версия`. Текстовый путь
не умирает никогда — он канонический формат обмена.

## Контракты на швах

- **Шов №1 (фронт → бэкенд)** — билдер `иск/иб.раз`. Эмиссия строкой
  (`иб_эми(иб, "    ПЕР АКК, 1", поз)`) или структурными операндами
  (`иб_инстр(иб, "ПЕР", иб_рег(...), иб_имм(...), поз)`). Позиция —
  строка/столбец в `.раз`-исходнике, не в `.иск`: сквозная диагностика
  и линейная карта для СЛЕДа получаются бесплатно.
- **Уровень 2 → 1** — `проход1(узлы) → *Прог`, планировщик цели → `*План`,
  `проход2(пр, пл) → *Дво`. Уже реализовано в `иск/сборщик.раз`.
- **Уровень 1 → 0** — `пе_строй`/`эльф_строй`/`махо_строй(пл, код, дан)`.
- **Фасад `иск/ипп.раз`** — единая точка входа:
  `ипп_собери(исх стр, цель стр) стр`, `ипп_дво(узлы, цель)`, `ипп_пиши`.
  `искра.exe` и `разум.exe` — тонкие драйверы над фасадом.

## Закладки, принятые в дизайне

1. **План памяти.** `*План.вид = файл|память`; раздвоение только в точке
   импортов (IAT-ячейка против реального адреса `GetProcAddress`). JIT
   становится ещё одним планировщиком, а не переписыванием сборщика.
2. **Карта отладки.** `*Дво` несёт необязательный буфер карты
   `(VA → файл:строка)` + символы/типы — контракт для СЛЕДа и `--отладка`.
3. **Линковка на уровне `*Прог`.** `прог_слей(пр1, пр2)` — раздельная
   компиляция и инкрементальный кэш модулей без объектных файлов:
   *Прог и есть объектный формат.
4. **Оптимизатор — два яруса навсегда.** Высокий на AST разума
   (инлайн, LICM, развёртка, свёртка); низкий на узлах инструкций
   (пипхол, регистры, выбор инструкций, автовекторизация). `опт.раз`
   мигрирует с текстовых строк на узлы.
5. **Цели.** Вся цель-специфика собрана в `ипп`; при появлении ARM64 —
   таблица `{цель → кодер, планировщик, эмиттер}` через `как функ(...)`.
6. **Лестницы входа для ЯР:** (а) ЯР → текст `.раз`; (б) ЯР → билдер `иб`;
   (в) ЯР → общий mid-IR между уровнями 4 и 3, когда понадобятся общие
   высокоуровневые оптимизации.

## Границы этапа Ж

- **Ж1:** `иск/иб.раз` (оба режима), `иск/ипп.раз`, `*План.вид`,
  карта в `*Дво`, `разум --прямо` (умолчание для `-о` и запуска),
  `опт` на узлах, позиции `.раз` в узлах инструкций.
- **Не входит:** структурные операнды повсеместно в гене (миграция
  постепенная), `прог_слей`, реализация плана-памяти, таблица целей,
  mid-IR для ЯР.
